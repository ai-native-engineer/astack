# 저자 의도 - 이 스킬이 왜 이렇게 설계됐나 (헌법)

> 작성자가 "커리큘럼/스킬 개선"을 요청할 때의 실제 의도. 이 스킬의 모든 게이트, 원칙이 여기서 나온다. 새 규칙을 더하거나 자료를 고치기 전, 이 의도와 맞는지 먼저 본다. (근거: 다회 반복된 사용자 피드백 + 게이트 코드. 검수/제작 시작 전 1회 읽는다.)

## 한 문장

AI 창작이 아니라, 사람(작성자, 동료 강사)이 만든 검증된 기존 자료를 베이스로 **약간의 개선만** 한다. 분석에서 멈추지 말고 실제로 고치되, **AI 자율 미감으로 새로 짓거나 멀쩡한 걸 방치 판단하지 않는다.**

## 3대 실패 패턴 (게이트가 막으려는 것)

1. **기존 자료를 안 보고 새로 지어냄** ("왜 기존 자료 안봤어?" 다회 반복)
   - 기존 검증 자료가 기본값이다. 신규 창작은 빠진 연결부에만. 강제: `explore` 게이트(authoring 3-0절 / review 0절).
2. **검수가 약점표/분석에서 멈춤** ("왜 이미지 개선 안하냐" 다회 반복)
   - 검수 = 실제로 고쳐진 자료. 제안, 약점 나열은 검수가 아니다. 강제: review.md 4절 / `gate-review`.
3. **AI 미감으로 품질을 판단** (사용자가 짚은 새 통찰)
   - AI가 "이 자료 좋다"고 방치하거나 "이 이미지 안 맞다"고 새로 만드는 것, 둘 다 금지. AI 품질 판단은 작성자 기준보다 관대하다 - 작성자가 별로라는 걸 AI는 좋다고 본다.

## 판단 원칙

- **기본값은 보존, 개선은 최소** - "개선"은 명시적 결함(누락, 오류, 낡음, AI 티 표기)만 외과적으로 고치는 것이다. 멀쩡한 톤, 구조, 이미지를 AI 취향으로 재작성하지 않는다. "약간의 개선만"이 사용자가 원하는 폭이다.
- **이미지는 '그 개념을 흔히 설명하는' 사람의 이미지 우선** - 이 자료에 100% 대응하는 전용 이미지를 찾으려 들지 않는다(그런 건 없다 - 못 찾았다고 생성으로 건너뛰는 게 사용자가 가장 자주 지적한 실수다). 그 개념을 설명할 때 많이 쓰이는 관용, 보편 이미지면 충분하다. **원본에 사람이 만든 실제 이미지(스크린샷, 로고, 도식)가 있으면 AI로 재생성하지 말고 ref와 caption 그대로 이식한다**(caption 빈 이미지 = AI 재생성 흔적). AI 생성은 사람 이미지도 웹 검색 이미지도 없을 때의 최후 수단이며, 세상에 실물이 없는 '이번 회차 산출물 결과 화면'에만 쓴다. 정본: image-generation-notion-assets.md intro.
- **AI 판단을 신뢰의 기준점으로 쓰지 않는다** - 좋다/나쁘다, 맞다/안 맞다를 AI 미감으로 결정하지 말고, 사람이 만든 검증 자료를 기준점(gold standard)으로 둔다. 확신이 안 서면 혼자 단정하지 말고 사용자에게 묻는다.
- **보여주면 말하지 않는다, 빼라면 완전히 뺀다** - 이미지, 링크, 북마크가 이미 보여주는 것을 그 위/아래에 안내 텍스트나 callout으로 또 설명하지 않는다("가입은 아래에서" 류 중복 금지). "빼라"는 지시는 요약해서 남기는 게 아니라 흔적 없이 제거다 - 섹션마다 도입, 안내 문장을 깔아야 한다는 강박을 버린다. 빈 섹션이 빈 안내보다 낫다.
- **반복 자체가 아니라 'AI가 매번 새로 지어내는 것'이 문제다** - 같은 보안 경고나 안내가 여러 번 나오는 것 자체는 죄가 아니다. 죄는 AI가 그때그때 다른 어투로 새로 써서 일관성이 깨지는 것이다(AI Slop). 같은 메시지를 반복할 거면 이전 자료에서 사용자가 쓰던 똑같은 문구를 글자 그대로 재사용한다 - 새로 지어내지 않는다. 이건 위 "기존 검증 자료가 기본값" 원칙이 텍스트, 보안 문구에도 똑같이 적용되는 것이다(실측: 4회차 보안 callout이 매 섹션 다른 어투로 새로 쓰여 거부됨).

## 균형 (한쪽으로 치우치지 않기)

"더 하라"가 아니라 "핵심만, 끝까지"다. 빈약화(신호 없는 설명 과잉)와 비대화(잡설, 과한 절차, 기존보다 디테일하게 다시 쓰기) **양쪽 모두 반려**된다. 원본 밀도가 분량 상한선이다(authoring 3-3절). 특히 **현 버전 UI에서만 통하는 세세한 절차(가입 단계, 버튼명, 설정값)는 금방 stale되니 링크와 실제 캡처로 대체**한다(anti-patterns.md 3절).
