# 강의 자료 조사 + 생성 (Phase 3~4 - 프로젝트 소스 탐색 + 회차 페이지 작성)

curriculum 스킬의 Phase 3(자료조사 = 3-0절)과 Phase 4(자료생성 = 3-1~3-6절) 세부. 기존 강의자료를 딥 탐색한 뒤 확정된 커리큘럼(design.md 1절)을 회차별 교안 `.md`로. 입문자, 비개발자 전제. (절 번호 `3-x`는 교차 인용되는 안정 앵커라 Phase 번호와 무관하게 유지한다.)

**강의 자료는 텍스트만 만들지 않고 관련 이미지도 함께 기획한다** - 개념 설명, 흐름 설명, 과제 안내, 도구 사용 절차에는 이해를 돕는 이미지가 기본으로 들어간다. 이미지를 넣는 구간은 **이미지 -> 본문 설명** 순서로 둔다.

**논리 구조는 항상 고객, 수강생 중심** - 만들거나 고칠 때의 사고 사슬은 1. 수강생 피드백, 설문이 말하는 것 -> 2. 만들고 싶다고 한 주제 -> 3. 그래서 이번 회차에 만드는 것 -> 4. 만들기 위해 가르칠 개념(기존 자료에서 이식) 순서다. 개념->실습 순으로 정리하지 않는다. 섹션 구성, 순서는 기존 틀을 유지해도 된다 - 바꾸는 것은 출발점: 도입을 "수강생이 적어낸 것 -> 오늘 만드는 것"으로 열고, 각 섹션이 2의 어느 업무에 닿는지 보이게 한다.

## 3-0. 기존 자료 탐색, 재사용 (작성 전 필수 - "참고"가 아니라 통째 이식)

**새 문장을 쓰기 전에 딥 탐색 산출물부터 만든다 - 이 산출물 없이 본문 작성 금지(딥 탐색 건너뜀 처방):**

**탐색 소스는 프로젝트 `AGENTS.md`가 선언한다.** 기본은 모듈 DB, Notion 원본, 로컬 교안이며, 구성되지 않은 소스는 억지로 요구하지 않는다. 모듈 DB나 Notion이 없으면 `--no-db`/`--no-notion`으로 명시하고 이유를 남긴다.

```text
# Notion을 쓰는 프로젝트는 공통 notion 스킬 절차로 pagination을 끝까지 따라가
# has_more=false인 완전한 search JSON을 먼저 만든다.
# 모듈 DB + 선택적 Notion + 로컬을 한 산출물로 묶는다.
python3 "${CLAUDE_PLUGIN_ROOT}/skills/curriculum/scripts/curriculum_gate.py" explore \
  --topic "<주제>" --workspace-id <workspace-id> --datasource <module-data-source-id> \
  --local-root <교안 루트> --notion-hits <search-results.json>
# Notion을 쓰지 않으면 --notion-hits 대신 --no-notion을 명시한다.
```

스크립트는 선언된 모듈 DB, Notion 검색 결과, 로컬 교안을 한 `curriculum-candidates-*.md`로 모은다. 기본 임계는 `--min-candidates 10`이지만 범위가 작거나 소스가 적으면 시간, 난이도, 산출물 범위를 근거로 낮춘다. 묵시적으로 생략하지 말고 조정값과 이유를 응답에 남긴다. 후보는 최신순으로 보여주되 최종 선택은 정확도, 수강생 적합성, 출처 안정성을 함께 본다. workspace/data-source 좌표와 인증은 프로젝트 `AGENTS.md` 및 notion 스킬이 정본이다.

Notion 후보는 `ntn pages get <page-id>`로, 로컬 후보는 해당 파일로 원문을 직접 열어 실제 설명 블록/프롬프트/이미지 ref를 확인한다. Notion 본문에 `<database ... data-source-url="collection://...">`나 `<page url="...">`가 있으면 한 단계 더 펼친다. 직접 비교한 후보만 산출물에서 `[x]` 체크하고 `근거:`를 채운 뒤 `최선 후보: <후보명>`을 남긴다. `python3 curriculum_gate.py gate-candidates curriculum-candidates-*.md`가 통과해야 작성에 들어간다.

**갱신형 작업은 explore 산출물을 소스 전수 검토로 대체한다** - 지정 공식 소스의 갱신분(문서 미러, 릴리스 노트)을 기존 발행 페이지에 반영하는 작업은 "기존 강의자료 10개" 형식이 성립하지 않는다. 대신 갱신 소스 전체 목록 + 채택/제외와 근거 + 타깃 페이지 매핑을 담은 candidates 파일을 만들고 응답에 대체 사유를 명시한다(묵시 생략 금지).

**위임 추출 수치는 원문 라인으로 재확인** - 서브에이전트가 요약해 온 수치/기간/비율은 보고만 믿지 말고 소스 원문 라인(`rg`)을 직접 확인한 뒤 본문에 넣는다. 요약 단계에서 수치가 미끄러진다(예: 원문 "an hour or two"가 "하루 만에"로 보고됨).

이미지 이식 규칙:
- 공개 미러(`*.notion.site`) 크롤 금지 - 본문이 깨지고 이미지 ref를 못 얻는다.
- 원본 본문의 `file://` attachment ref를 **그대로 유지**해 이식한다(노션이 대상 워크스페이스로 복제, 보존). get이 내보낸 만료 S3 URL은 .md에 박지 않는다.
- file:// ref 없는 새 로컬 PNG, 다른 워크스페이스 자립화 등 보존 규칙 상세는 [`image-generation-notion-assets.md`](image-generation-notion-assets.md) 1절, 2절이 정본.

강의 자료는 **검증된 모듈 선별 -> 고객, 수강생 맥락에 맞게 조립 -> 부족한 연결부만 새로 작성** 순서로 만든다. 프로젝트가 선언한 기존 자료에서 관련 모듈을 고르고 원본 흐름, 프롬프트, 미디어를 보존한 뒤 도메인 사례와 과제만 치환한다. 최근 실험 초안보다 오래 쓰이며 검증된 자료를 우선한다.

**환류 질문(작성 후)**: 탐색한 기존 자료에서 가져와 새로 조립한 검증 블록 중 재사용 가치가 있는 것은, 작성을 마친 뒤 사용자에게 "이 모듈을 `강의 모듈` DB에 적재할까요?"를 물어 환류한다(적재 절차는 [`module-bank.md`](module-bank.md)). 임의로 적재하지 않는다 - DB는 사용자가 큐레이션한다.

모듈 선택 기준은 문장 취향이 아니라 **설명 정확도, 수강생 적합성, 과제 연결성, 재사용성, 출처 안정성**이다.

검증된 자료가 있으면 새로 쓰지 않고 **원문을 통째로 가져와 도메인(고객사, 팀, 예시)만 치환**한다. 통째의 범위: 문장, 설명 빌드업 흐름, 프롬프트 코드블록, 템플릿 형식, 이미지, 영상, 첨부 ref, details 접기 전문. 검증된 문장이 새로 쓴 문장보다 톤, 눈높이가 낫고, 기존 자료의 밀도가 곧 상한선이다(3-3절). 이식 출처는 커리큘럼 변경이력 또는 README 템플릿 계보에 남기고, 학습자용 본문에는 `자료 출처:` aside를 넣지 않는다. **반대로, 형식(섹션 제목, 표 틀)만 복사하고 변수만 치환하거나 구체(명령어, 출처, 실제 화면)를 "구체화->계획->구현" 같은 일반 라벨로 희석하는 것은 이식이 아니라 slop이다 - 실질(신호)까지 가져온다. 이미 명령어, 출처로 채워진 원본을 추상 라벨로 "정렬"하지 말 것.**

**이미지 출처 우선순위**(기존 자료 이식 -> 공식 출처 -> 실제 화면 캡처 -> net-new 결과 화면/목업 생성)는 [`image-generation-notion-assets.md`](image-generation-notion-assets.md) intro가 정본이다. 받거나 캡처한 이미지는 그 파일 2절로 삽입한다.

**미디어 게이트 (작성 완료 시 필수)** - 세 검사를 모두 통과한다:

1. **로컬 이식 대조** - `python3 curriculum_gate.py verify-media <원본.md> <교안.md>` -> 누락 0. 의도적으로 뺀 것만 예외다. 이 검사는 live Notion 페이지를 읽지 않는다. **"반영 완료" 단정은 이 통과 + notion-sync round-trip이 있을 때만**이다.
2. **섹션 분포** - 섹션별 이미지 수를 센다(`re.split('^# ')` 후 `file://` count). 개념, 흐름, 절차, 과제 요구사항, 세팅, 설치, UI 조작 섹션이 텍스트만으로 남으면 기존 자료, 공식 출처, 실제 화면 캡처에서 이미지를 찾는다. 생성은 아직 존재하지 않는 net-new 결과 화면/목업에만 쓴다. 핵심 미디어(PRD 설명 이미지 등)는 빠뜨리지 않는다.
3. **산출물 시각자료 확보** - 이번 회차의 핵심 산출물이 실제로 존재하면 결과 화면을 캡처한다. 아직 존재하지 않는 net-new 산출물이면 결과 화면/목업을 생성한다. 다른 도메인의 개념 이미지로 결과 화면을 대신하지 않는다.

이미지 배치, 생성 규칙(본문 섹션 안에 이미지 먼저, 프로젝트 톤, 로고 레퍼런스 검증, SVG/오버레이 금지, 한글 확대검수)은 [`image-generation-notion-assets.md`](image-generation-notion-assets.md)가 정본 - 새 이미지나 로컬 PNG를 넣기 전 그 파일을 먼저 읽는다.

## 3-1. 노션 페이지 골격 (ntn 확장 마크다운) - 단일 템플릿

- **라이브**는 [`template.md`](template.md), **VOD**는 [`vod-clip-template.md`](vod-clip-template.md)를 쓴다. 자료가 많은 라이브 회차만 [`notion-session-page-template.md`](notion-session-page-template.md)의 child-page 변형을 쓴다.
- **frontmatter를 업로드 본문에 넣지 말 것** - `ntn pages update`가 `---\ntitle:…\n---`를 본문 첫 블록으로 박는다. 업로드용은 **첫 콘텐츠 블록부터** 시작. 노션 **페이지 제목 속성이 곧 제목**이라 본문에 `# 제목`, `> 부제` 메타헤더, 여는 `---`를 중복으로 넣지 않는다. 맨 앞 `---` 블록은 review-draft `frontmatter`가 강제 검출.
- 라이브 골격 순서: **목표 callout(최소완료 + 선택확장) -> (선택) 타임라인 표 -> 섹션 토글들 -> Q&A/과제.**
- **타임라인은 선택** - 시간이 정해진 **라이브(실시간) 회차**면 맨 위에 두고, **영상 클립, 짧은 포맷**이면 생략하고 목표 callout부터 시작한다. 쓸 땐 **시간 | 내용 2컬럼 표**.
- **라이브 타임라인 기본값은 50분 강의 + 10분 휴식**이다. 계약 시간, 장소 규칙, 수강생 난이도에 맞지 않으면 프로젝트 `AGENTS.md`의 시간표로 덮어쓴다. 한 블록 안의 여러 토픽은 한 행 내용 칸에 명사구로 묶는다.
- 섹션: `# N. 제목 {toggle="true"}`(또는 `# STEP n. 제목`), 토글 내용 탭 1개 들여쓰기, 소제목 들여쓴 `## 소제목`.
- callout `<callout icon="…" color="gray_bg"> … </callout>`(내부 탭), 접기 `<details><summary>요약</summary> …탭… </details>`. **`<aside>`, `> [!NOTE]`는 금지**(평탄화됨, review-draft `aside`가 강제) - 전부 `<callout>`로.
- **코드펜스 언어는 내용에 맞게 명시**: 여는 펜스에 내용 종류를 적는다 - JSON은 `json`, JS Code 노드 코드는 `javascript`, System Message/프롬프트(마크다운 본문)는 `markdown`, 명령/표현식/필드, 설정 나열 등 일반 텍스트는 `text`. 빈 펜스는 노션이 JavaScript로 기본 지정해 한글에 엉뚱한 하이라이팅이 나니 항상 언어를 적는다.
- **노드 연결, 프로세스 흐름은 `mermaid` 코드블록으로**: 단계 흐름(A -> B -> C), 분기, 폴링 루프를 `text` 펜스 안 ASCII 화살표로 그리지 않고 노션이 렌더하는 `mermaid` `flowchart`로 그린다(ASCII 다이어그램 금지, anti-patterns.md 4절). 복붙 프롬프트, 명령, 설정 나열은 흐름이 아니니 해당 언어 코드블록 그대로 둔다.
- **코드펜스 중첩 금지**: 코드블록 안에 또 다른 여는 펜스(예 안쪽 json 펜스)를 넣으면 렌더가 깨진다 - 안쪽은 'JSON 형식:'처럼 풀어쓰고 본문 펜스 개수는 짝수로 맞춘다.
- 색상은 노션 표준만(주로 `gray_bg`/`yellow`/`red`/`blue_bg`). 발명색은 review-draft `nonstd-color`가 강제 차단.

## 3-2. 번호, 목차

- 섹션 번호 **정수 1~N, 1부터 연속**. 소수/끊김은 `review-draft`가 경고하므로 검수에서 해소한다.

## 3-3. 콘텐츠 원칙 (입문자, 비개발자)

- **개념은 명료하게 - 정의 -> 직관 -> 단계**: 개념을 설명할 땐 1. **한 줄 정의**(무엇인지) -> 2. 필요하면 **작동, 구성 한 줄** -> 3. **직관적 단계로 쪼개** 각 단계에 **복붙 프롬프트**를 붙인다(template.md 골격 리듬). 잡설을 빼는 것과 개념을 흐리는 것은 다르다 - 안심, 동기부여는 빼되 개념 자체는 또렷하게 남긴다.
- **산문 최소, 불렛/넘버링/표 우선**: 설명을 줄글 문단으로 늘어놓지 않는다. 단계는 넘버링, 나열은 불렛, 비교는 표로 적는다. 줄글은 한두 문장 연결부에만 쓴다. 전체 줄 수/이미지/콜아웃 수로 컴팩트하다고 판단하지 말고 **문단 밀도**를 본다. 120자 이상 산문, 3줄 이상 연속 산문, 한 문단 안에 정의/이유/행동/확인까지 섞은 블록은 결함이다. 항목을 불렛/표/프롬프트/체크리스트로 분리하고, 리드 문장은 첫 불렛으로 흡수하거나 삭제한다(아래 2형태 원칙). **고치는 방법은 항목을 불렛/넘버링/표로 분리하는 것이지 문장을 더 짧게 압축하는 게 아니다** - 게이트 dense-prose 플래그를 문장 압축으로 피하면 빽빽한 AI-terse 결함이 된다(1-2줄 자연 산문은 허용). 압축 대신 "이 줄이 여러 항목을 담았나? -> 불렛으로 분리"를 먼저 묻는다.
- **2형태 원칙 (본문 덩어리 형식)**: 헤딩/표/이미지/코드펜스/콜아웃 태그 사이의 본문 덩어리는 두 형태만 허용한다 - (a) 순수 불렛/넘버링 목록, (b) 독립 줄글 1~2줄. 리드 줄글 + 불렛, 불렛-줄글-불렛 교차, 3줄 이상 연속 줄글은 금지한다. 검증: `python3 "${CLAUDE_PLUGIN_ROOT}/skills/curriculum/scripts/format_scan.py" <교안.md ...>` 위반 0.
- **용어 첫 등장 1줄 풀이**(예 "MVP = 가장 작게 일단 되는 버전"). 톤: "완벽하지 않아도 됨/할 수 있는 만큼", 존댓말, 부담 낮게.
- **용어 풀이를 `용어(설명)` 괄호 형식으로 달지 않는다** - "CLI(까만 화면에서...)", "환경변수(API 키처럼...)" 식 괄호 인라인 풀이는 AI 글쓰기 대표 패턴이라 읽기 어색하다. 대신 세 가지 중 하나를 선택: 1. 뒤 셀, 옆 문장에 이미 설명이 있으면 용어만 씀, 2. 본문 문장이면 "환경변수란 앱이 몰래 참고하는 설정값으로," 식 자연스러운 문장으로 녹임, 3. 비개발자 말로 대체 가능하면 기술 용어 자체를 쓰지 않음.
- **출처는 인라인 텍스트로 박지 않고 북마크 카드로 단다**: 도구 기능, 가격, 정책, 보안, API, 버전별 동작처럼 검증이 필요한 내용은 공식 문서를 확인하되, **문장 끝 `[출처: URL]` 표기는 금지**(AI 티로 읽혀 사용자가 강하게 거부). 대신 그 주장을 담은 섹션 하단에 **공식 문서 북마크 카드 1개**를 둔다(북마크 생성은 notion-sync.md 4-2절). 본문에 `[출처:]` 텍스트 0, 출처 aside나 참고문헌 섹션도 금지.
- 실습마다 **복붙 가능한 프롬프트/명령**. 막힘 대처는 "에러 화면 복사 -> AI에게"로 일원화(정본 live-lecture-operations-tips.md 4절).
- **실습 프롬프트는 비개발자가 직접 친다는 가정으로 쓴다**: 학습자(예: 회계 담당자)가 자기 업무 말로 요청하는 문장이어야 한다. 기술 용어("단일 페이지 웹 도구", "칸반", "API 호출은 서버에서")를 학습자 입에 넣지 말고, 필요한 기술 지시는 일상어로 풀어 프롬프트 안에 담는다(예: "키가 사용자 화면(브라우저)에 드러나면 안 돼").
- **Claude Code 실습형 자료는 원문 후보 선택 후 이식**: 새 실습 단계를 창작하지 않는다. 먼저 [`claude-code-practice-source-selection.md`](../templates/claude-code-practice-source-selection.md) 템플릿으로 ntn 원문 후보를 정리하고, 사용자가 고른 원문의 단계명/순서/강조를 그대로 따른다.
- **도착점 먼저**(강사가 완성본을 짧게 시연 후 시작). 실습 목표 수는 시간, 난이도, 산출물 크기에 따라 정한다. 모든 회차에 **최소완료**를 하나 이상 두고, 시간이 남을 때만 수행할 **선택확장**을 분리한다. 한 블록에 풀코스를 넣지 않는다.
- **AI 티, 채움말 제거**: 대본/본문은 `humanize-korean` 기준으로 전수 스캔한다 - 순수 필러, 안심 상투("겁먹지 마세요"), 경구 마무리는 **통삭제**, 개념 반복은 **한 줄 콜백**("앞에서처럼…")으로 압축, 마무리는 경구 대신 **다음 행동**으로. 이미 촬영/확정된 회차는 제외.
- **블록 테스트 (자료 비대의 최대 원인)**: 모든 블록(콜아웃, 산문, 리스트)은 수강생이 *뭘 보고/칠지*(명령어, 출처, 실제 화면 같은 신호)만 담는다. **빼도 할 일이 안 줄면 삭제** - 핵심을 3문장으로 풀지 말고 명령어 한 줄, 실제 화면으로. 안심으로 신호를 희석하지 않는다.
- **원본 밀도가 상한선**: 텍스트, 콜아웃이 검증된 이식 원본보다 불어나면 비대.
- **콜아웃 예산**: 콜아웃(`<callout>`)은 **용어 1줄 정의, 가드(보안/책임/주의), 복붙(프롬프트/명령), 꼭 튀어야 할 핵심 1줄**만 쓴다. 이모지는 🚨(보안/치명), ⚠️(주의/가드), 🤔(짚고 갈 질문/왜), 💡(핵심/용어 정의) 4개로 제한(그 외는 review-draft `callout-emoji`가 잡음).
- **금지 콜아웃**: 안심, 부연, 동기부여, 막힘 안내("많아 보여도 괜찮아요", "당황하지 마세요" 류)는 콜아웃으로 만들지 않는다 - 본문에 녹이거나 삭제(같은 당부 1회). 한 섹션 콜아웃 3개 초과면 남발 신호. **같은 보안 가드/안내 반복은 새로 짓지 말고 이전 검증 자료의 똑같은 문구로 재사용**(정본과 이유는 author-intent.md).
- **추상화 수준 - 기존 자료보다 디테일하게 쓰지 않는다**: 주제, 세팅, 필수 설명, 복붙 프롬프트만 둔다. 단계마다 대처 문장을 깔아주는 떠먹이기 표, "딱 맞음/맞음" 판정 컬럼, 시연 1~6 표 같은 과잉 구조화는 AI 티의 대표 형태. 검증된 기존 실습 자료의 밀도가 상한선이다. **서비스 가입/설정의 현 버전 UI 절차(단계 표, 버튼명, 설정값)도 stale되니 쓰지 않는다 - 링크와 실제 캡처로(anti-patterns.md 3절).**
- **구체, 담백 - 추상, 비유, 클리셰 금지**: 1. *"~같은 단계가 따로 필요해요"* 식 얼버무림, 학습자가 모를 용어(webhook 등)로 뭉뚱그린 추상 설명, 2. "정공법, 명예제, 필살기, 치트키" 같은 단정, 과장 클리셰 라벨 - 둘 다 'AI가 쓴 티'로 읽혀 사용자가 강하게 거부한다. **구체 사실로 쓰고, 구체적으로 못 쓰면 그 문장을 뺀다.** (예: "진짜로 막으려면 영수증 확인 같은 단계가 따로 필요" -> "결제 여부와 상관없이 버튼만 누르면 열려요". "한국에선 이게 정공법" -> 빼거나 "사업자 없이 결제받는 현실적인 방법".)
- **결론엔 근거 한 줄 / 강조엔 구체 장면 / 도구는 나눠주는 순간 정의**: 결론("빠르다/중요하다")만 두지 말고 작동 방식 한 줄을, 추상어 대신 구체 장면 1개를, 도구/파일은 나눠주는 순간 정의를 붙인다. 청중이 "그래서 왜?"를 되물으면 근거를 뺀 신호다. 구체 예시와 라이브 즉흥 설명은 [`live-lecture-delivery-tips.md`](live-lecture-delivery-tips.md)가 정본.

## 3-4. 안전, 일관성 / 도메인 매칭

- **위험, 보안 우회 명령(인증서 검증 끄기 등)은 자료 어디에도 넣지 말 것** - 학습자 본문은 물론 강사용 메모에도 박지 않는다. 막히면 표준 막힘 대처(에러 화면 복사 -> AI, 안 풀리면 강사/사내 IT가 직접)로.
- **스코프, 책임 가드**: 도구가 못 하는 범위를 **가드 콜아웃**으로 미리 좁힌다(예 "법규 검토는 건폐율, 용적률만", "종합 소견은 AI 자동작성 금지 -> 기술자 검토 필요로 표시"). 전체 자동화를 약속하지 말 것. (가드는 콜아웃 예산 3-3절의 허용 용도 - 단 같은 가드 반복 말고 필요한 곳에만.)
- **내부 모순 금지**(도착점 "직접 완성" <-> "그건 보너스" / "계속 쓰는 도구" <-> "새로고침하면 사라짐"). 저장 안 되면 "시제품", 되면 "도구".
- 예시, 데모는 **수강생 실제 업무**에서(특히 라이브/B2B). 이식 시 도구 화면은 재활용 가능하나 **결과물 화면**은 도메인 다르면 그대로 쓰지 않는다.

## 3-5. 라이브(실시간) 강의 운영

시간이 정해진 라이브 회차는 [`live-lecture-operations-tips.md`](live-lecture-operations-tips.md)와 [`live-lecture-delivery-tips.md`](live-lecture-delivery-tips.md)를 따른다. 회차별 패턴, 실패, 해법은 shared skill이 아니라 **해당 프로젝트의 `context/` 운영 로그나 `AGENTS.md`**에 기록한다. 강사 메모와 진행 노트는 학습자 본문에 넣지 않고 프로젝트 로컬 큐시트로 분리한다.

## 3-6. 자기검수 게이트 (초안 != 완료 - 무조건)

초안을 만들었다고 끝이 아니다. **제작은 Phase 5 자기검수 루프를 통과해야 완료**다. 검수는 별도 진입도 가능하지만 자료생성 직후에는 제작의 필수 마무리다.

[`review.md`](review.md) 하네스를 그대로 돌린다(딥 탐색은 3-0에서 이미 했으니 review 0절은 건너뜀): review-draft 린트 -> 사용자 관점 페르소나 비평 -> **실제 개선(텍스트 + 이미지 생성, 약점표 금지)** -> iterate -> 검수 리포트. 단계 상세는 review.md가 정본.

반영(Phase 6) 전제: review.md 6절 반영 게이트를 통과한다. `notion_reflect.py`는 단일 page/md pair, 기대 title/parent/last-edited, 현재 candidates/report를 모두 요구한다. 통과 없이 반영하지 않는다.
