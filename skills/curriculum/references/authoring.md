# 강의 자료 생성 (Phase 3 - 회차 페이지 작성, 도구 비종속)

curriculum 스킬의 Phase 3 세부. 확정된 커리큘럼(design.md 1절)을 회차별 교안 `.md`로. 입문자, 비개발자 전제.

**강의 자료는 텍스트만 만들지 않고 관련 이미지도 함께 기획한다** - 개념 설명, 흐름 설명, 과제 안내, 도구 사용 절차에는 이해를 돕는 이미지가 기본으로 들어간다. 이미지를 넣는 구간은 **이미지 -> 본문 설명** 순서로 둔다.

**논리 구조는 항상 고객, 수강생 중심** - 만들거나 고칠 때의 사고 사슬은 1. 수강생 피드백, 설문이 말하는 것 -> 2. 만들고 싶다고 한 주제 -> 3. 그래서 이번 회차에 만드는 것 -> 4. 만들기 위해 가르칠 개념(기존 자료에서 이식) 순서다. 개념->실습 순으로 정리하지 않는다. 섹션 구성, 순서는 기존 틀을 유지해도 된다 - 바꾸는 것은 출발점: 도입을 "수강생이 적어낸 것 -> 오늘 만드는 것"으로 열고, 각 섹션이 2의 어느 업무에 닿는지 보이게 한다. (실증 2026-06-11 선엔지니어링 3회차)

## 3-0. 기존 자료 탐색, 재사용 (작성 전 필수 - "참고"가 아니라 통째 이식)

**새 문장을 쓰기 전에 딥 탐색 산출물부터 만든다 - 이 산출물 없이 본문 작성 금지(#3 딥 탐색 건너뜀 처방):**

**탐색 소스는 항상 셋 다: 강의 모듈 DB + 강의자료 워크스페이스/조직 노션 전수 + 로컬 교안.** 강의 모듈 DB는 아직 빈약해 그것만 보면 "검증 자료가 없다"고 잘못 결론내고 모듈 DB에 고착한다(실측 #3). 모듈 DB가 비어도 강의자료 워크스페이스와 조직 노션 전체에 검증된 회차 자료가 있으니 반드시 함께 본다.

```text
# 1) 강의자료 워크스페이스 + 조직 노션 전수 검색 - 워크스페이스별 토큰으로 /search.
agents-env run 'NOTION_API_KEY@<org-ws-token>' -- sh -c 'NOTION_API_TOKEN={{NOTION_API_KEY}} NOTION_WORKSPACE_ID=<org-workspace-id> ntn api /search -d "{\"query\":\"<주제>\"}"' > notion-search-org.json
agents-env run NOTION_API_KEY@<lecture-ws-token> -- sh -c 'NOTION_API_TOKEN={{NOTION_API_KEY}} NOTION_WORKSPACE_ID=<lecture-workspace-id> ntn api /search -d "{\"query\":\"<주제>\"}"' > notion-search-lecture.json
# 2) 모듈 DB + 노션 전수 + 로컬을 한 산출물로
python3 ~/.agents/skills/shared/curriculum/scripts/curriculum_gate.py explore \
  --topic "<주제>" --workspace-id <org-workspace-id> --datasource <강의모듈 ds-id> --local-root <교안 프로젝트들 루트> \
  --notion-hits notion-search-org.json notion-search-lecture.json
```

스크립트가 강의 모듈 DB(`ntn datasources query --limit 1000`, has_more면 cursor 루프) + 노션 전수 검색 결과(`--notion-hits`) + 로컬 교안(`rg`)을 한 `curriculum-candidates-*.md` 후보 목록으로 모은다. **참고 자료를 최신순 10개 이상**(기본 임계 `--min-candidates 10`) 모으지 못하거나 DB/노션 미탐색이면 MISS+비0이라 통과 못 한다 - 이게 "기존 자료를 안 봤다"의 재발 차단선이다(지정 소스 하나만 보고 시작하지 않는다). 후보는 **최신순(최근 수정일 우선)**으로 정렬돼 각 줄 앞에 `(YYYY-MM-DD)` 수정일이 붙으니, 낡은 초안보다 최근 검증 자료를 먼저 떠본다. 니치 주제라 10개가 안 되면 `--min-candidates`를 낮추되 응답에 사유를 명시한다(묵시 우회 금지). workspace/ds id와 조직 워크스페이스 토큰는 프로젝트 AGENTS.md(notion-sync 4-2절, 조직별로 달라 스킬에 박지 않음), 모르면 `ntn datasources resolve <db-id>`로 풀거나 AGENTS.md를 먼저 확인한다. 강의자료 워크스페이스는 `<lecture-ws-token>` 토큰을 쓴다. `<company-ws-token>` 토큰은 회사 데이터용이라 curriculum 강의자료 탐색에 쓰지 않는다. 노션 search는 워크스페이스별 토큰 단위라 강의자료/조직를 각각 돌려 둘 다 `--notion-hits`로 넘긴다. 끝내 못 떠도 묵시 통과로 삼지 말고, 의도적 제외는 `--no-db`/`--no-notion`으로 명시한다. (아래에서 `curriculum_gate.py`로 줄여 쓴다.)

각 후보는 `ntn pages get <page-id>`로 원문을 떠서 실제 설명 블록/프롬프트/이미지 ref를 확인하고, 본문에 `<database ... data-source-url="collection://...">`나 `<page url="...">`가 있으면 한 단계 더 펼친다. 같은 조직 기존 과정(노션 원본)도 후보에 포함한다. 떠서 비교한 후보만 산출물에서 `[x]` 체크하고 `근거:`를 채운 뒤 `최선 후보: <후보명>`을 남긴다. `python3 curriculum_gate.py gate-candidates curriculum-candidates-*.md`가 통과해야 작성에 들어간다.

이미지 이식 규칙:
- 공개 미러(`*.notion.site`) 크롤 금지 - 본문이 깨지고 이미지 ref를 못 얻는다.
- 원본 본문의 `file://` attachment ref를 **그대로 유지**해 이식한다(노션이 대상 워크스페이스로 복제, 보존). get이 내보낸 만료 S3 URL은 .md에 박지 않는다.
- file:// ref 없는 새 로컬 PNG, 다른 워크스페이스 자립화 등 보존 규칙 상세는 [`image-generation-notion-assets.md`](image-generation-notion-assets.md) 1절, 2절이 정본.

강의 자료는 **검증된 모듈 선별 -> 고객, 수강생 맥락에 맞게 조립 -> 부족한 연결부만 새로 작성** 순서로 만든다. "좋은 문장 참고"가 아니라, 기존에 잘 설명된 모듈을 강의안의 부품으로 다루는 방식이다. 새 자료를 만들 때는 `강의 모듈` DB와 강의자료 워크스페이스/조직 노션 전수 양쪽에서 프로토타이핑/MVP/PRD/바이브 코딩/도구 실습/막힘 대처 같은 모듈을 고르고, 원본 흐름, 프롬프트, 미디어를 보존한 뒤 고객사 사례와 과제만 치환한다. 최근 실험 자료나 오염 가능성이 있는 초안보다 오래 쓰이며 검증된 자료(출처 안정성)를 우선한다.

**환류 질문(작성 후)**: 노션 전수에서 가져와 새로 조립한 검증 블록 중 재사용 가치가 있는 것은, 작성을 마친 뒤 사용자에게 "이 모듈을 `강의 모듈` DB에 적재할까요?"를 물어 환류한다(적재 절차는 [`module-bank.md`](module-bank.md)). 임의로 적재하지 않는다 - DB는 사용자가 큐레이션한다.

모듈 선택 기준은 문장 취향이 아니라 **설명 정확도, 수강생 적합성, 과제 연결성, 재사용성, 출처 안정성**이다.

검증된 자료가 있으면 새로 쓰지 않고 **원문을 통째로 가져와 도메인(고객사, 팀, 예시)만 치환**한다. 통째의 범위: 문장, 설명 빌드업 흐름, 프롬프트 코드블록, 템플릿 형식, 이미지, 영상, 첨부 ref, details 접기 전문. 검증된 문장이 새로 쓴 문장보다 톤, 눈높이가 낫고, 기존 자료의 밀도가 곧 상한선이다(3-3절). 이식 출처는 커리큘럼 변경이력 또는 README 템플릿 계보에 남기고, 학습자용 본문에는 `자료 출처:` aside를 넣지 않는다. **반대로, 형식(섹션 제목, 표 틀)만 복사하고 변수만 치환하거나 구체(명령어, 출처, 실제 화면)를 "구체화->계획->구현" 같은 일반 라벨로 희석하는 것은 이식이 아니라 slop이다 - 실질(신호)까지 가져온다. 이미 명령어, 출처로 채워진 원본을 추상 라벨로 "정렬"하지 말 것.**

**이미지 출처 우선순위**(이식 -> 웹 검색 로고/서비스/개념 -> 무로그인 캡처 -> Codex)는 [`image-generation-notion-assets.md`](image-generation-notion-assets.md) intro가 정본이다. 받거나 캡처한 이미지는 그 파일 2절로 삽입한다.

**미디어 게이트 (작성 완료 시 필수)** - 세 검사를 모두 통과한다:

1. **로컬 이식 대조** - `python3 curriculum_gate.py verify-media <원본.md> <교안.md>` -> 누락 0(원본 작업본의 미디어 ref가 교안에 전부 있는지 대조, exit 비0이면 빠진 ref 출력). 의도적으로 뺀 것만 예외. 이 검사는 live Notion 페이지를 읽지 않는다. **"반영 완료" 단정은 이 통과 + notion-sync/notion_reflect round-trip이 있을 때만**(#7 처방).
2. **섹션 분포** - 섹션별 이미지 수를 센다(`re.split('^# ')` 후 `file://` count). 개념, 흐름, 절차, 과제 요구사항, 세팅, 설치, UI 조작 섹션이 텍스트만으로 남으면 원본이나 관련 자료에서 이미지를 찾거나 만든다. 핵심 미디어(PRD 설명 이미지 등)는 빠뜨리지 않는다. 텍스트만 옮기고 이미지, 첨부를 빠뜨리는 것이 단골 실패다.
3. **산출물 시각자료 생성** - 이 회차에서 새로 만드는 핵심 산출물, 새 대표 예시, 새 도메인이 있으면 그 산출물의 목업, 흐름, 결과 화면을 **새로 만든다**. 다른 도메인의 기존 개념 이미지로 때우면 미달(3-4절). 이번 산출물 자체를 보여주는 시각자료가 있는지 따로 확인한다.

이미지 배치, 생성 규칙(본문 섹션 안에 이미지 먼저, Codex 톤, 한국어 프롬프트, 로고 레퍼런스 검증, SVG/오버레이 금지, 한글 확대검수)은 [`image-generation-notion-assets.md`](image-generation-notion-assets.md)가 정본 - 새 이미지나 로컬 PNG를 넣기 전 그 파일을 먼저 읽는다.

## 3-1. 노션 페이지 골격 (ntn 확장 마크다운) - 단일 템플릿

- 골격은 [`template.md`](template.md) **하나**를 복사해 채운다. 자료가 많아 한 페이지가 길어지는 회차는 [`notion-session-page-template.md`](notion-session-page-template.md)처럼 섹션을 **child_page로 분리하는 변형**을 쓴다(골격은 동일, 분리만 다름).
- **frontmatter를 업로드 본문에 넣지 말 것** - `ntn pages update`가 `---\ntitle:…\n---`를 본문 첫 블록으로 박는다. 업로드용은 **첫 콘텐츠 블록부터** 시작. 노션 **페이지 제목 속성이 곧 제목**이라 본문에 `# 제목`, `> 부제` 메타헤더, 여는 `---`를 중복으로 넣지 않는다. 맨 앞 `---` 블록은 review-draft `frontmatter`가 강제 검출.
- 골격 순서: **(선택) 타임라인 표 -> "이번 시간에 하는 것" 목표 callout -> "오늘 끝나면" 도착점 callout -> 섹션 토글들 -> Q&A/과제.**
- **타임라인은 선택** - 시간이 정해진 **라이브(실시간) 회차**면 맨 위에 두고, **영상 클립, 짧은 포맷**이면 생략하고 목표 callout부터 시작한다. 쓸 땐 **시간 | 내용 2컬럼 표**.
- **라이브 타임라인 = 50분 강의 블록 + 10분 휴식 블록의 반복**(50/10/50/10…). **한 블록(50분)을 25/30분으로 더 쪼개지 않는다** - 그 안의 여러 토픽은 한 행 내용 칸에 `• 토픽<br>• 토픽` 명사구로 묶는다. 블록 수는 총 강의 시간에 맞춘다(2시간 = 50/10/50/10). 쉬는 시간 행 `<span color="yellow">`, 마무리/케어 `<span color="red">`.
- 섹션: `# N. 제목 {toggle="true"}`(또는 `# STEP n. 제목`), 토글 내용 탭 1개 들여쓰기, 소제목 들여쓴 `## 소제목`.
- callout `<callout icon="…" color="gray_bg"> … </callout>`(내부 탭), 접기 `<details><summary>요약</summary> …탭… </details>`. **`<aside>`, `> [!NOTE]`는 금지**(평탄화됨, review-draft `aside`가 강제) - 전부 `<callout>`로.
- **코드펜스 언어는 내용에 맞게 명시**: 여는 펜스에 내용 종류를 적는다 - JSON은 `json`, JS Code 노드 코드는 `javascript`, System Message/프롬프트(마크다운 본문)는 `markdown`, 명령/표현식/필드, 설정 나열 등 일반 텍스트는 `text`. 빈 펜스는 노션이 JavaScript로 기본 지정해 한글에 엉뚱한 하이라이팅이 나니 항상 언어를 적는다.
- **노드 연결, 프로세스 흐름은 `mermaid` 코드블록으로**: 단계 흐름(A -> B -> C), 분기, 폴링 루프를 `text` 펜스 안 ASCII 화살표로 그리지 않고 노션이 렌더하는 `mermaid` `flowchart`로 그린다(ASCII 다이어그램 금지, anti-patterns.md 4절). 복붙 프롬프트, 명령, 설정 나열은 흐름이 아니니 해당 언어 코드블록 그대로 둔다.
- **코드펜스 중첩 금지**: 코드블록 안에 또 다른 여는 펜스(예 안쪽 json 펜스)를 넣으면 렌더가 깨진다 - 안쪽은 'JSON 형식:'처럼 풀어쓰고 본문 펜스 개수는 짝수로 맞춘다.
- 색상은 노션 표준만(주로 `gray_bg`/`yellow`/`red`/`blue_bg`). 발명색은 review-draft `nonstd-color`가 강제 차단.
- **톤, 구조 표준 문서**: 회차가 여럿이거나 작성자가 둘 이상이면 프로젝트 `02-output/_톤-표준.md`를 단일 소스로 둔다 - 1. 자료 유형(실습형/개념형) 구분 2. 콜아웃 이모지->용도 고정 매핑 3. 폼 보존 원칙(제목, 구분선, 이미지). 매 회차 톤 재발명을 막는다.

## 3-2. 번호, 목차

- 섹션 번호 **정수 1~N, 1부터 연속**(소수/끊김은 review-draft가 강제). **복습, 도입은 `# 0` 허용**. 워밍업을 실한 본문 섹션으로 승격하지 말고 `# 0`(또는 1번 도입부, 인트로 callout)에 둔다.
- **섹션 최소 분량** - "불렛 몇 개 = 섹션 하나" 금지. 콜아웃 1개, 불렛 3~4개뿐이면 인접 섹션에 합치거나 callout 흡수. 합칠 때 `STEP N` 교차참조, 하위번호도 정리(끊긴 참조 금지).
- 타임라인 "내용" 칸은 **명사구**(설계 의도, 내부 메모 금지). 나쁨 `2부 - 설계서가 X의 확장임…` / 좋음 `3. 만들 것 설계하기`.

## 3-3. 콘텐츠 원칙 (입문자, 비개발자)

- **개념은 명료하게 - 정의 -> 직관 -> 단계**: 개념을 설명할 땐 1. **한 줄 정의**(무엇인지) -> 2. 필요하면 **작동, 구성 한 줄** -> 3. **직관적 단계로 쪼개** 각 단계에 **복붙 프롬프트**를 붙인다(template.md 골격 리듬). 잡설을 빼는 것과 개념을 흐리는 것은 다르다 - 안심, 동기부여는 빼되 개념 자체는 또렷하게 남긴다.
- **산문 최소, 불렛/넘버링/표 우선**: 설명을 줄글 문단으로 늘어놓지 않는다. 단계는 넘버링, 나열은 불렛, 비교는 표로 적는다. 줄글은 한두 문장 연결부에만 쓴다. 전체 줄 수/이미지/콜아웃 수로 컴팩트하다고 판단하지 말고 **문단 밀도**를 본다. 120자 이상 산문, 3줄 이상 연속 산문, 한 문단 안에 정의/이유/행동/확인까지 섞은 블록은 결함이다. 1줄 목적 -> 불렛/표/프롬프트/체크리스트로 쪼갠다. **고치는 방법은 항목을 불렛/넘버링/표로 분리하는 것이지 문장을 더 짧게 압축하는 게 아니다** - 게이트 dense-prose 플래그를 문장 압축으로 피하면 빽빽한 AI-terse 결함이 된다(1-2줄 자연 산문은 허용). 압축 대신 "이 줄이 여러 항목을 담았나? -> 불렛으로 분리"를 먼저 묻는다.
- **용어 첫 등장 1줄 풀이**(예 "MVP = 가장 작게 일단 되는 버전"). 톤: "완벽하지 않아도 됨/할 수 있는 만큼", 존댓말, 부담 낮게.
- **용어 풀이를 `용어(설명)` 괄호 형식으로 달지 않는다** - "CLI(까만 화면에서...)", "환경변수(API 키처럼...)" 식 괄호 인라인 풀이는 AI 글쓰기 대표 패턴이라 읽기 어색하다. 대신 세 가지 중 하나를 선택: 1. 뒤 셀, 옆 문장에 이미 설명이 있으면 용어만 씀, 2. 본문 문장이면 "환경변수란 앱이 몰래 참고하는 설정값으로," 식 자연스러운 문장으로 녹임, 3. 비개발자 말로 대체 가능하면 기술 용어 자체를 쓰지 않음.
- **출처는 인라인 텍스트로 박지 않고 북마크 카드로 단다**: 도구 기능, 가격, 정책, 보안, API, 버전별 동작처럼 검증이 필요한 내용은 공식 문서를 확인하되, **문장 끝 `[출처: URL]` 표기는 금지**(AI 티로 읽혀 사용자가 강하게 거부). 대신 그 주장을 담은 섹션 하단에 **공식 문서 북마크 카드 1개**를 둔다(북마크 생성은 notion-sync.md 4-2절). 본문에 `[출처:]` 텍스트 0, 출처 aside나 참고문헌 섹션도 금지.
- 실습마다 **복붙 가능한 프롬프트/명령**. 막힘 대처는 "에러 화면 복사 -> AI에게"로 일원화(정본 live-lecture-operations-tips.md 4절).
- **실습 프롬프트는 비개발자가 직접 친다는 가정으로 쓴다**: 학습자(예: 회계 담당자)가 자기 업무 말로 요청하는 문장이어야 한다. 기술 용어("단일 페이지 웹 도구", "칸반", "API 호출은 서버에서")를 학습자 입에 넣지 말고, 필요한 기술 지시는 일상어로 풀어 프롬프트 안에 담는다(예: "키가 사용자 화면(브라우저)에 드러나면 안 돼"). 실증 2026-06-10 고객사 D.
- **Claude Code 실습형 자료는 원문 후보 선택 후 이식**: 새 실습 단계를 창작하지 않는다. 먼저 [`claude-code-practice-source-selection.md`](../templates/claude-code-practice-source-selection.md) 템플릿으로 ntn 원문 후보를 정리하고, 사용자가 고른 원문의 단계명/순서/강조를 그대로 따른다.
- **도착점 먼저**(강사가 완성본 짧게 시연 후 시작). **개인 실습 목표는 1개 고정**. **시간 현실성**(한 블록에 풀코스 금지, 데모는 "완성본+한 부분 라이브 수정+준비된 환경"으로 압축).
- **AI 티, 채움말 제거**: 대본/본문은 `humanize-korean` 기준으로 전수 스캔한다 - 순수 필러, 안심 상투("겁먹지 마세요"), 경구 마무리는 **통삭제**, 개념 반복은 **한 줄 콜백**("앞에서처럼…")으로 압축, 마무리는 경구 대신 **다음 행동**으로. 이미 촬영/확정된 회차는 제외.
- **블록 테스트 (자료 비대의 최대 원인)**: 모든 블록(콜아웃, 산문, 리스트)은 수강생이 *뭘 보고/칠지*(명령어, 출처, 실제 화면 같은 신호)만 담는다. **빼도 할 일이 안 줄면 삭제** - 핵심을 3문장으로 풀지 말고 명령어 한 줄, 실제 화면으로. 안심으로 신호를 희석하지 않는다.
- **원본 밀도가 상한선**: 텍스트, 콜아웃이 검증된 이식 원본보다 불어나면 비대.
- **콜아웃 예산**: 콜아웃(`<callout>`)은 **용어 1줄 정의, 가드(보안/책임/주의), 복붙(프롬프트/명령), 꼭 튀어야 할 핵심 1줄**만 쓴다. 이모지는 🚨(보안/치명), ⚠️(주의/가드), 🤔(짚고 갈 질문/왜), 💡(핵심/용어 정의) 4개로 제한(그 외는 review-draft `callout-emoji`가 잡음).
- **금지 콜아웃**: 안심, 부연, 동기부여, 막힘 안내("많아 보여도 괜찮아요", "당황하지 마세요" 류)는 콜아웃으로 만들지 않는다 - 본문에 녹이거나 삭제(같은 당부 1회). 한 섹션 콜아웃 3개 초과면 남발 신호. **같은 보안 가드/안내 반복은 새로 짓지 말고 이전 검증 자료의 똑같은 문구로 재사용**(정본과 이유는 author-intent.md).
- **추상화 수준 - 기존 자료보다 디테일하게 쓰지 않는다**: 주제, 세팅, 필수 설명, 복붙 프롬프트만 둔다. 단계마다 대처 문장을 깔아주는 떠먹이기 표, "딱 맞음/맞음" 판정 컬럼, 시연 1~6 표 같은 과잉 구조화는 AI 티의 대표 형태. 검증된 기존 실습 자료의 밀도(미니 실습 1개 = 프롬프트 코드블록 3~4개 + 스크린샷 수준)가 상한선이다. **서비스 가입/설정의 현 버전 UI 절차(단계 표, 버튼명, 설정값)도 stale되니 쓰지 않는다 - 링크와 실제 캡처로(anti-patterns.md 3절).**
- **구체, 담백 - 추상, 비유, 클리셰 금지**: 1. *"~같은 단계가 따로 필요해요"* 식 얼버무림, 학습자가 모를 용어(webhook 등)로 뭉뚱그린 추상 설명, 2. "정공법, 명예제, 필살기, 치트키" 같은 단정, 과장 클리셰 라벨 - 둘 다 'AI가 쓴 티'로 읽혀 사용자가 강하게 거부한다. **구체 사실로 쓰고, 구체적으로 못 쓰면 그 문장을 뺀다.** (예: "진짜로 막으려면 영수증 확인 같은 단계가 따로 필요" -> "결제 여부와 상관없이 버튼만 누르면 열려요". "한국에선 이게 정공법" -> 빼거나 "사업자 없이 결제받는 현실적인 방법".)
- **결론엔 근거 한 줄 / 강조엔 구체 장면 / 도구는 나눠주는 순간 정의**: 결론("빠르다/중요하다")만 두지 말고 작동 방식 한 줄을, 추상어 대신 구체 장면 1개를, 도구/파일은 나눠주는 순간 정의를 붙인다. 청중이 "그래서 왜?"를 되물으면 근거를 뺀 신호다. 구체 예시와 라이브 즉흥 설명은 [`live-lecture-delivery-tips.md`](live-lecture-delivery-tips.md)가 정본.

## 3-4. 안전, 일관성 / 도메인 매칭 / 글로서리

- **위험, 보안 우회 명령(인증서 검증 끄기 등)은 자료 어디에도 넣지 말 것** - 학습자 본문은 물론 강사용 메모에도 박지 않는다. 막히면 표준 막힘 대처(에러 화면 복사 -> AI, 안 풀리면 강사/사내 IT가 직접)로.
- **스코프, 책임 가드**: 도구가 못 하는 범위를 **가드 콜아웃**으로 미리 좁힌다(예 "법규 검토는 건폐율, 용적률만", "종합 소견은 AI 자동작성 금지 -> 기술자 검토 필요로 표시"). 전체 자동화를 약속하지 말 것. (가드는 콜아웃 예산 3-3절의 허용 용도 - 단 같은 가드 반복 말고 필요한 곳에만.)
- **내부 모순 금지**(도착점 "직접 완성" <-> "그건 보너스" / "계속 쓰는 도구" <-> "새로고침하면 사라짐"). 저장 안 되면 "시제품", 되면 "도구".
- 예시, 데모는 **수강생 실제 업무**에서(특히 라이브/B2B). 이식 시 도구 화면은 재활용 가능하나 **결과물 화면**은 도메인 다르면 그대로 쓰지 않는다.
- **교차 강의 글로서리**: 한 강사가 여러 강의를 병행하면 공통 개념(용어 정의, 디버깅 절차, 트러블슈팅)을 `강의_공통_설명표준.md` 한 곳에 통일한다 - `✅ 이미 일치 / 통일 필요 / 적용 체크리스트` 구조.

## 3-5. 라이브(실시간) 강의 운영

시간이 정해진 라이브 회차는 **계획대로 안 끝나는 게 정상**(영상 클립엔 불필요). 시간 관리, 환경/권한, 강사 큐시트, 막힘 대처 같은 **운영 노하우는 [`live-lecture-operations-tips.md`](live-lecture-operations-tips.md)가 정본**이다 - 라이브 회차를 설계할 때 그 파일을 먼저 읽는다. 개념을 **말로 푸는 설명, 전달 디테일**(결론+근거, 구체 장면, 도구 즉시 정의)은 [`live-lecture-delivery-tips.md`](live-lecture-delivery-tips.md)에 별도 누적한다(3-3절과 직결). **둘 다 회차를 진행하며 계속 누적, 갱신하는 살아있는 문서** - 새 패턴/실패/해법을 로그에 날짜와 함께 추가하고 일반화되면 카테고리로 승격한다. **강사 메모, 진행 노트는 학습자 노션 본문에 넣지 않고 이 큐시트로 분리한다**(anti-patterns.md 4절).

## 3-6. 자기검수 게이트 (초안 != 완료 - 무조건)

초안을 만들었다고 끝이 아니다. **제작은 자기검수 루프를 통과해야 완료**다 - 초안 띡 금지(선엔지니어링 "쓰레기를 만든거야, 핵심만 남겨야지", 고객사 B "화면만 보여주면 어떡하나, 실습도 같이 있어야지"). 검수는 별도 Phase가 아니라 **제작의 마지막 단계**다.

[`review.md`](review.md) 하네스를 그대로 돌린다(딥 탐색은 3-0에서 이미 했으니 review 0절은 건너뜀): review-draft 린트 -> 사용자 관점 페르소나 비평 -> **실제 개선(텍스트 + 이미지 생성, 약점표 금지)** -> iterate -> 검수 리포트. 단계 상세는 review.md가 정본.

반영(Phase 4) 전제: review.md 6절 반영 게이트(`gate-review` exit 0 - 검수 리포트 존재 + 교안 고신호 smell 0). `notion_reflect.py`를 쓰면 `--report <검수.md>`를 넘겨 gate-review를 다시 통과시킨다. 통과 없이 반영 금지.
