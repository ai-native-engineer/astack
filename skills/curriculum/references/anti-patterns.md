# 피해야 할 AI 티 (표기, 패턴)

> 강의 자료(노션 회차 페이지, 교안)에 쓰면 "AI가 썼다"는 티가 나는 표기와 패턴. 작성, 이식 후 이 목록으로 전수 점검한다. 1번 기호 규칙은 강의 산출물뿐 아니라 이 스킬 문서 저작 자체에도 똑같이 적용한다. 어휘, 톤 클리셰는 authoring.md 3-3절, humanize-korean 스킬과 한 세트.

## 1. 기호, 표기 - 사람이 안 쓰는 특수문자

키보드로 잘 안 치는 특수기호다. AI만 쓴다. 일반 문장부호로 바꾼다.

| 피할 표기 | 대신 | 예 |
|---|---|---|
| `→` (화살표) | `->` | 복사 -> 붙여넣기 |
| `—` (em dash, 긴 줄표) | `-` | 배포 - 인터넷에 올리는 것 |
| `·` (가운뎃점) | `,` 또는 `/` | A, B, C  /  설치/실행 |
| `①②③`, `㉠` (동그라미 숫자, 문자) | `1.` `2.` `3.` | 1. 준비  2. 실행 |
| `§` (섹션 기호) | 빼고 절 번호만 | "3-3절", "준비 단계" |

## 2. 어휘, 톤 클리셰 (authoring.md 3-3절과 연계)

- 클리셰 라벨: "정공법, 명예제, 필살기, 치트키" 같은 단정, 과장 표현 -> 빼거나 구체 사실로.
- 추상, 얼버무림: "~같은 단계가 따로 필요해요", 학습자가 모를 용어(webhook 등)로 뭉뚱그리기 -> 구체로 쓰고, 못 쓰면 그 문장을 뺀다.
- 안심 상투: "겁먹지 마세요", "당황하지 마세요", "코드 읽지 마세요" -> 통삭제.
- 괄호 인라인 풀이: "CLI(까만 화면...)" -> 뒷문장에서 자연스럽게 풀거나 용어를 안 쓴다.
- `[출처: URL]` 인라인 표기 -> 본문에 출처 텍스트를 박지 않는다. 검증 주장의 출처는 섹션 하단 **북마크 카드**로 단다(authoring.md 3-3절, notion-sync.md 4-2절). 사용자가 가장 강하게 거부하는 AI 티다.

상세는 authoring.md 3-3절, 메모리 feedback_avoid_ai_cliche_phrasing.

## 3. 현 버전 UI에 묶인 세세한 절차 (stale 유발)

서비스 가입 단계, 버튼명("New Project"), 설정값("Region, database password"), 클릭 순서를 단계별로 나열하지 않는다 - 서비스 UI는 자주 바뀌어 강의 자료가 금방 틀려진다("이런게 AI Slop이야"). 대신 **서비스 링크(북마크) + 실제 화면 캡처**로 대체한다. 링크와 캡처가 이미 "여기서 가입"을 보여주므로 **그 위에 "가입은 아래에서", "미리 만들어 옵니다" 같은 안내 텍스트나 callout을 또 달지 않는다** - 보여주는 자료가 self-explanatory하면 말로 중복하지 않는다. 북마크 카드 생성은 notion-sync.md 4-2절.

## 4. 학습자 자료에 섞지 말 것

- **강사 메모, 진행 노트** - 시연 팁, 시간 조절, 강사용 캡처 안내 같은 강사용 정보를 학습자 노션 본문에 넣지 않는다(`<details>`로 숨겨도 안티패턴). 강사용은 별도 큐시트(live-lecture-operations-tips.md)로 분리한다.
- **코드블록 ASCII 아트 다이어그램** - 흐름도, 구조도를 코드펜스 안 박스, 화살표 ASCII로 그리지 않는다. 노드/프로세스 흐름은 `mermaid` 코드블록(노션 `mermaid` 렌더), 그 외 시각자료는 실제 이미지로 한다. 코드블록 언어 규칙 정본은 authoring.md 3-3절.

## 5. 점검

작성, 이식 직후 1번 기호를 검색해 강의 본문(코드펜스, URL 제외)에서 0인지 확인한다.

```text
rg -n '→|—|·|[①-⑳]|§|\[출처' <파일>
```
