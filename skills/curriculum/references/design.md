# 커리큘럼 설계 + 자료 조사 (Phase 1~2)

curriculum 스킬의 Phase 1(설계), Phase 2(자료 조사) 세부. 도구 비종속. `[대괄호]`는 상황에 맞게 채운다.

---

## 1. 커리큘럼 설계 (Backward Design)

"무엇을 가르칠까"가 아니라 **"교육 후 무엇을 할 수 있어야 하나"**에서 시작한다.

### 1-1. 프로젝트 구조 / 초기화

```
YYMMDD-프로젝트명/
├── 01-context/   # 입력 전부: company/(project-context-gather 수집 아카이브+attachments), references/(참고자료), data/(실습+raw/원본), README.md(인덱스), 1차자료 .md
├── 02-output/    # 산출물: 회차별 교안 .md, 대시보드, assets/
├── 99-archives/  # 옛 버전/완료 회차/녹화 보관
├── prompts/      # AI 세션 기록(YYYY-MM-DD.json), root 한 곳만(Claude Code 훅)
├── curriculum-v1.md  # 커리큘럼 초안(버전별)
└── README.md     # 프로젝트 개요(대상, 기간, 목표)
```

네이밍: 폴더 `YYMMDD-고객명[-주제]`(예 `260325-고객사`) / 01-context `YYMMDD-출처-내용.md` / prompts `YYYY-MM-DD.json`(root 한 곳). 커리큘럼 파일은 `curriculum-v{N}.md`가 기본이되 `curriculum-draft-v{N}.md`, 접미사형(`_초안`->`_최종본`)도 허용 - **위치(root/02-output)와 접두는 재량, 단 버전 상단 변경이력 헤더는 필수**(1-5절).

> **폴더 규약(2026-06 표준)**: 신규는 `01-context`/`02-output`/`99-archives` 넘버링. 기존 `context/`,`output/` 프로젝트는 도구가 `01-context` 있으면 그걸, 없으면 `context`를 쓴다(하위호환). `prompts/`는 Claude Code 훅 소관이라 안 건드린다.

초기화: 디렉토리 생성 -> `README.md`(대상, 기간, 목표) + `01-context/README.md`(인덱스 표). 인덱스를 별도 README로 안 두면 프로젝트 `AGENTS.md` 본문에 둬도 된다(2절).

### 1-2. context에서 교수설계 정보 추출

| 정보 | 질문 | 출처 |
|---|---|---|
| 학습자 | 누가 배우나(직무, 경험, 인원) | 킥오프 회의록 |
| 목표 | 교육 후 무엇을 할 수 있어야 하나 | 고객 요구사항 |
| 제약 | 시간, 도구, 예산, 장소, **사내망/권한** | 미팅 합의 |
| 선행 지식 | 이미 아는 것/모르는 것 | 피드백, 설문 |
| 평가 | 성과를 어떻게 측정하나 | 고객 KPI |

라이브, 기업 교육은 **환경(사내망, 방화벽, 관리자 권한)이 당일 붕괴 요인** - 제약에 이를 명시하고 [`live-lecture-operations-tips.md`](live-lecture-operations-tips.md) 2절의 사전 리허설 게이트로 선검증한다.

### 1-3. 최종 목표 -> 차시 분해 -> 평가 먼저

- **최종 수행 목표**: `[과정] 수료 후 학습자는 [동사]+[대상]+[조건]+[기준]`. 동사는 관찰 가능하게("이해한다"❌ -> "설명/제작/분석할 수 있다"✅).
- **차시별 목표 분해**: 각 목표는 구체적, 측정 가능, 달성 가능, 최종목표 관련성.
- **평가 먼저 설계**(콘텐츠보다 먼저): 실습 결과물(기술 습득) / 발표(종합) / 퀴즈(지식) / 과제(현업 적용). 각 평가는 합격선을 1줄로 박는다(`미달 | 충족 | 우수`) - 충족선은 1-4절 "매 차시 산출물 ≥1", 라이브 전원 사수선과 일치시킨다.

### 1-4. 커리큘럼 표 작성

설계, 제안 단계의 상세표는 6컬럼: `차시(챕터명) | 차시명 | 차시목표(~할 수 있다 2~3개) | 교수방법(강의/시연/실습/과제/토론/코칭) | 주요 훈련내용 | 학습활동/프로젝트([실습]/[프로젝트]/[과제] 태그)`. (차시명의 `N-1. 스텝명` 하위번호는 선택. B2C 영상 강의는 6컬럼 대신 1-6절의 `Part>Chapter>Clip` 계층표를 쓴다.)

작성 원칙: 1. 실습 중심 - 비율은 가이드(이론 30, 실습 70 권장)이고 핵심은 "따라하기"가 아닌 **"내 업무 적용"**(영상 클립은 데모 비중이 커질 수 있음) 2. 매 차시 산출물 ≥1 3. 점진적 복잡도(개념->가이드 실습->자율 프로젝트) 4. 직무 연결(수강생 실제 업무 데이터 - 라이브/B2B에서 강하게, B2C는 범용 예제) 5. 차시 간 연결(복습으로 시작, 예고로 마무리).

### 1-5. 버전 관리

`curriculum-v1`(초안) -> v2(고객 피드백) -> v3(파일럿 후) -> v4(실강 후) -> v5(확정). v3/v4 개정 근거(평가 데이터)는 파일럿, 실강의 전원 사수선 달성, 막힘 지점, 운영 로그([`live-lecture-operations-tips.md`](live-lecture-operations-tips.md) 7절)에서 끌어온다. 파일명 형식은 재량이나 **각 버전 상단 변경이력 헤더는 필수**:
```
> 변경: v2 -> v3
> - 3차시 실습 개인->팀(피드백 "혼자 막막"), 5차시 분량 축소(시간 초과)
```
버전 변경은 상단 변경이력 헤더에만 남기고, 독자가 옛 버전 맥락을 알아야 이해되는 잔여 설명은 지운다.

### 1-6. B2B vs B2C / 제안 단계

설계 전략 차원의 구분(페이지 템플릿은 authoring.md 노션 골격으로 공통):

| 차원 | B2B(기업 교육) | B2C(온라인 강의) |
|---|---|---|
| 목표 | 업무 성과 | 개인 역량/커리어 |
| 실습 | 회사 실제 데이터 | 범용 예제 |
| 평가 | 현업 적용+상사 확인 | 과제+수료증 |
| 산출물 | 제안서, 주차별 교안(02-output/) | `Part>Chapter>Clip` 계층표 |

- **B2C 동영상 강의** 납품용 계층표: `Part 명 | Ch 번호 | Ch 명 | Clip 번호 | Clip 명`.
- **B2B 제안 단계**: 제안서가 첫 산출물인 경우가 많다. **고객 제출용 제안서**(다크모드 HTML: 배경, 목표, 전제, 차시표(압축 5컬럼), 운영, 비용, 일정, 다음 단계)와 **내부 설계용 `curriculum-v{N}`**(상세 6컬럼)을 분리한다. 제안 단계는 **설계만 하고 `02-output/` 회차 교안, 노션 반영 없이 멈추는 정식 단계**로 인정. 사내망, 권한 등 **사전 리허설 검증 항목과 열린 항목**을 제안서/커리큘럼에 트래킹한다.

## 2. 자료 조사 (context 수집)

커리큘럼 품질은 context 풍부함에 비례한다. **수집은 `project-context-gather` 스킬에 위임**한다 - 다중 소스(Obsidian, Notion, Slack, Google Workspace) 검색, 음성 메모 전사, 소스당 1개 통합 아카이브 + 원본 attachments 보존, `01-context/` 저장까지 그 스킬이 한다. 이 결과를 받아 설계(이 파일)와 작성(authoring.md)에 쓴다.

인덱싱: `01-context/README.md`나 프로젝트 `AGENTS.md`에 `| 파일 | 날짜 | 내용 | 상태 |` 표로 유지(선택).
