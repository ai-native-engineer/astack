# 강의 자료 검수/개선 하네스 (제작의 필수 마무리 + 단독 Phase 5)

> 검수는 선택이 아니라 **제작의 필수 마무리**다. 초안을 내고 끝내지 않는다 - "초안 띡" 금지(선엔지니어링 "쓰레기를 만든거야, 핵심만 남겨야지").
> 두 진입점, 같은 하네스: **(a) 제작(Phase 3) 직후 자기검수** - 입력은 방금 만든 초안(딥 탐색은 authoring 3-0에서 이미 함, 0절 건너뜀). **(b) 단독** - 입력은 이미 있는 자료(0절부터).
> **산출물은 약점 표가 아니라 실제로 고쳐진 자료 + 검수 리포트다.** 분석에서 멈추면 검수가 아니다(고객사 A/고객사 B/고객사 C "왜 이미지 개선은 안하는 거야 대체?" 반복, 한 회차 1차 무효).
> 게이트 스크립트 = `~/.agents/skills/shared/curriculum/scripts/curriculum_gate.py`(아래 `curriculum_gate.py`로 줄임). **게이트 통과 = exit 0 + 응답에 출력 인용**(SKILL 품질 게이트).

## 0. 딥 탐색 (단독 진입만 - #3 처방)

기존 검증 자료를 충분히 봤나에서 출발한다(고객사 A/고객사 B "왜 기존 자료 안봤어"). 제작 직후 자기검수는 authoring 3-0에서 이미 했으니 건너뛴다.

- 탐색 소스는 항상 셋 다: 강의 모듈 DB + 노션(강의자료/조직) 전수 + 로컬 교안. 모듈 DB는 빈약하니 그것만 보고 고착 금지.
- 명령(3소스 explore -> 후보 산출물 -> gate-candidates 통과)은 authoring 3-0절이 정본이다 - 그대로 따른다.
- `[x]` 체크는 `ntn pages get`으로 실제로 떠서 비교한 후보만. 최선 1개 선택 + 왜 최선인지 근거 한 줄(기준: 정확도/적합성/밀도/출처 안정성/이미지).

## 1. 기계 린트 - "초안 띡" smell (먼저, 싸게)

`python3 curriculum_gate.py review-draft <교안.md>` -> 신호 없는 섹션(복붙/이미지/체크리스트 0 = 화면만/설명만), **이미지 없는 산출물/결과/화면 섹션(needs-image, "왜 이미지 개선 안하냐" 직격)**, **긴 산문 블록(dense-prose: 줄 수/이미지 수로 통과 금지, 문단 밀도 검사)**, AI slop 기호, 안심말, 빈 펜스, 노션 표기/구조(frontmatter, `<aside>`, 비표준색, 소수/끊긴 번호, 콜아웃 이모지)를 file:line으로. **고신호면 비0.** 빈 체크박스/빈 펜스는 신호로 안 쳐준다(게이밍 차단). 기계가 잡는 건 사람 시간 안 쓰니 페르소나 비평 전에 먼저 고친다. **기계 lint가 잡은 표기는 위반 후보일 뿐 판정이 아니다** - 기존 자료엔 일괄 적용하지 말고 그 자료의 표기 관행과 대조해 의도분을 가린 뒤 고친다(자동 카운트만으로 대량 치환 금지). 신규 저작엔 anti-patterns 기준 그대로.

## 2. 사용자 관점 페르소나 비평 (핵심 - 작성자 != 비평자)

초안 작성자가 아니라 **fresh-context 비평자**가 사용자 입장에서 본다 - 큰 회차는 `curriculum-reviewer` 서브에이전트 병렬(서로 다른 페르소나, 편향 없이; 검수 리포트만 받고 개선/iterate는 메인이), 짧은 클립은 자기비평. 검수를 `notion-explorer`(노션 좌표 찾기용 haiku 탐색기)에 보내지 않는다 - 탐색 전용이라 검수하면 그럴듯한 오정정을 낸다. **거시 우선**(구조/신호/실습/이미지), 표기 미시는 1절 린트에 맡기고 nitpick 금지("거시적으로 봐야지" 처방).

페르소나(해당하는 것만):
- **수강생(입문자/비개발자)** - 이 단계 따라하다 어디서 막히나? 처음 보는 용어 설명 있나? 내가 **직접 칠 프롬프트/할 실습**이 있나, 아니면 화면만 보여주나("실습도 같이 있어야지")? 설명만 많고 "뭘 보고/칠지" 신호가 없나?
- **강사(라이브)** - 이 순서로 시간 안에 되나? 환경/권한 당일 붕괴 지점? 시연 -> 실습 흐름이 자연스럽나?
- **발주처(B2B)** - 우리 실제 업무 데이터/사례에 닿나? 약속한 성과에 연결되나?

규칙:
- **pre-emit 인용 게이트** - 모든 지적은 교안의 해당 줄(파일:줄 또는 인용)을 단다. **인용 못 하면 폐기**(근거 없는 추측 지적 금지 - 고객사 A 환각 처방, [[feedback_verify_external_data_access_before_trusting]]).
- 각 지적: `차원 | 인용 위치 | 문제 | 심각도 | 바꿀 내용`. 차원 정본은 아래 표.
- **false-positive 억제** - 이미 충분히 쉬운 설명을 "더 풀라", 원본 밀도 이내인데 "더 채우라"는 nitpick 금지(비대 유발).

## 3. 환각 차단 게이트 (page-id/이미지 실존)

지적/반영에 적은 모든 page-id는 실존 확인: `agents-env run NOTION_API_KEY@<ws> -- python3 curriculum_gate.py verify-pages <page-id> ...` -> **404(환각)면 비0**, 단정/반영 금지. **401/403(미공유)는 404로 오판 말고 정직 표기 + 공유 요청**. 서브에이전트 비평에 맡길 때도 이 결과를 응답에 인용하게 요구한다.

## 4. 개선 = 실행 (본체 - "왜 이미지 개선 안하냐" 직격, 제안에서 멈추지 않는다)

페르소나 발견 + 린트를 **실제로 고친다**. 약점 표로 끝내지 않는다. **단 개선은 명시적 결함(누락/오류/낡음/AI 티)만 외과적으로 - 멀쩡한 기존 자료를 AI 미감으로 재작성하지 않는다**(author-intent.md: 약간의 개선만, AI 판단 불신).

1. **텍스트** - 신호 없는 섹션에 복붙 프롬프트/실습 추가, slop/안심말 삭제, 설명 과잉을 핵심 신호로.
2. **이미지 - 실제로 확보한다**(가장 자주 빠뜨리는 단계). 출처 우선순위(정본 image-generation-notion-assets.md intro)로 확보, 삽입. **개념 이미지는 검색/이식이 먼저고 100% 대응 추구 금지, Codex 생성은 세상에 실물 없는 산출물 결과 화면 최후 수단**(author-intent). **이미 박힌 이미지가 원본의 실제 이미지를 AI로 대체한 것인지 확인 - caption 빈 이미지/원본과 다른 이미지는 AI 재생성 신호니 원본 ref로 교체**(고객사 A 1회차 실측). 사이트 링크는 화면 캡처 대신 북마크 카드로도 넣는다(notion-sync 4-2절).
3. **증거(반영 전)** - `review-draft <교안.md>` 재실행으로 고신호 smell이 줄었는지(before -> after), `verify-media <원본> <교안.md>`(원본 = 3-0 이식 원본 작업본(자기검수) 또는 0절 최선 후보(단독))로 로컬 이식 이미지가 안 빠졌는지 확인한다. **새 산출물/도메인이면 `verify-media <원본> <교안.md> --require-new`로 이식 외 새 이미지 1개 이상 확보를 강제**("왜 이미지 개선 안하냐" - 기존 이식만으론 통과 못 함; 개념은 검색/이식, 생성은 산출물 화면만). 이 검사는 live Notion 페이지 검증이 아니므로, 반영 후 round-trip은 별도다. **출력을 응답에 인용**, "고쳤다" 단정은 이 증거가 있을 때만.

## 5. iterate-until-pass (종료조건)

2 -> 4를 반복한다. **종료조건**: (a) `review-draft` 고신호 0 **AND** (b) 페르소나 비평이 2라운드 연속 material 발견 없음, **또는** (c) 사용자 만족. 보통 2~3라운드. 그래도 남으면 남은 약점을 정직하게 보고하고 사용자 판단을 받는다(무한 반복/혼자 단정 금지).
- **짧은 클립/이미 촬영된 회차는 단일 패스 허용** - review-draft 0이고 material 페르소나 발견이 없으면 1라운드로 종료. 라운드 수 채우려는 빈 반복은 금지(과한 절차도 비대다).

## 6. 검수 리포트 산출물 + 반영 (게이트)

- **검수 리포트** `검수-<회차>.md`를 남긴다 - 라운드별 `페르소나 발견(인용) | 실제 바꾼 것 | review-draft/verify-media before->after`.
- **게이트(반영 전제)** - `python3 curriculum_gate.py gate-review --candidates curriculum-candidates-*.md --report 검수-<회차>.md <교안.md>`가 exit 0이어야 반영한다(후보 검토 근거 + 리포트 존재 + 교안 고신호 smell 0 재확인). 이거 없이 노션 반영 금지(약점표만 내고 끝 방지).
- **반영** - notion-sync 4-0절 파괴적 쓰기 게이트(직접 API 신뢰 채널 + diff 사용자 승인) -> update -> 4-3절 round-trip 재검증. `notion_reflect.py --report <검수.md>`로 반영하면 gate-review를 다시 실행한다. `--skip-gate`는 의도적 우회일 때만 쓴다.

## 검수 차원과 정본 (재서술 금지, 포인터만)

| 차원 | 무엇을 보나 | 정본 |
|---|---|---|
| 논리 구조 | 고객/수강생 중심 사고 사슬인가 | authoring 도입부 |
| 신호/실습 | 수강생이 뭘 보고/칠지, 실습이 있나 | authoring 3-3절, 1절 린트 no-signal |
| 개념 명료성 | 정의->단계->프롬프트 리듬, 잡설 없나 | authoring 3-3절 |
| AI 티 표기 | 화살표/em dash/가운뎃점/섹션기호 | anti-patterns.md, 1절 린트 |
| 미디어 | 이미지 누락/출처/배치 | authoring 3-0절, verify-media |
| 안전선, 모순 | 내부 모순, 위험 명령 | SKILL 불변원칙 |
| 분량 | 원본 밀도 이내 | authoring 3-3절 |

## 실행 흐름

(단독은 0절 explore 먼저) -> review-draft 린트 -> 페르소나 비평(인용 게이트) -> verify-pages -> 실제 개선(텍스트+이미지) -> review-draft/verify-media before->after -> iterate(종료조건) -> 검수 리포트 -> 반영 -> round-trip.
