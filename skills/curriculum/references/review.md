# 강의 자료 검수/개선 하네스 (제작의 필수 마무리 + 단독 Phase 5)

> 검수는 선택이 아니라 **제작의 필수 마무리**다. 초안을 내고 끝내지 않는다.
> 두 진입점, 같은 하네스: **(a) 제작(Phase 4) 직후 자기검수** - 입력은 방금 만든 초안(딥 탐색은 authoring 3-0에서 이미 함, 0절 건너뜀). **(b) 단독** - 입력은 이미 있는 자료(0절부터).
> **산출물은 약점 표가 아니라 실제로 고쳐진 자료 + 검수 리포트다.** 분석에서 멈추면 검수가 아니다.
> 게이트 스크립트 = `${CLAUDE_PLUGIN_ROOT}/skills/curriculum/scripts/curriculum_gate.py`(아래 `curriculum_gate.py`로 줄임). **게이트 통과 = exit 0 + 응답에 출력 인용**(SKILL 품질 게이트).

## 0. 딥 탐색 (단독 진입만)

기존 검증 자료를 충분히 봤는지부터 확인한다. 제작 직후 자기검수는 authoring 3-0에서 이미 했으니 건너뛴다.

- 탐색 소스는 프로젝트 `AGENTS.md`가 선언한다. 모듈 DB, Notion, 로컬 교안 중 구성된 소스를 함께 보고, 제외한 소스는 `--no-db`/`--no-notion`과 이유를 남긴다.
- 명령(3소스 explore -> 후보 산출물 -> gate-candidates 통과)은 authoring 3-0절이 정본이다 - 그대로 따른다.
- `[x]` 체크는 Notion 원문이나 로컬 파일을 직접 열어 비교한 후보만 한다. 최선 1개 선택 + 왜 최선인지 근거 한 줄(기준: 정확도/적합성/밀도/출처 안정성/이미지).

## 1. 기계 린트 - "초안 띡" smell (먼저, 싸게)

`python3 curriculum_gate.py review-draft <교안.md>` -> 신호 없는 섹션, 이미지 없는 산출물/결과 섹션, 긴 산문 블록, AI slop 기호, 빈 펜스, Notion 표기/구조 오류를 file:line으로 잡는다. 고신호면 비0이다. 빈 체크박스/빈 펜스는 신호로 세지 않는다. 기존 자료는 프로젝트 표기 관행과 대조해 의도된 표현을 가린 뒤 고치고, 신규 저작은 anti-patterns 기준을 그대로 적용한다.

## 2. 사용자 관점 페르소나 비평 (핵심 - 작성자 != 비평자)

초안 작성자가 아니라 **fresh-context 비평자**가 사용자 입장에서 본다 - 큰 회차는 `curriculum-reviewer` 서브에이전트 병렬(서로 다른 페르소나, 편향 없이; 검수 리포트만 받고 개선/iterate는 메인이), 짧은 클립은 자기비평. 검수를 `notion-explorer`(노션 좌표 찾기용 haiku 탐색기)에 보내지 않는다 - 탐색 전용이라 검수하면 그럴듯한 오정정을 낸다. **거시 우선**(구조/신호/실습/이미지), 표기 미시는 1절 린트에 맡기고 nitpick 금지("거시적으로 봐야지" 처방).

페르소나(해당하는 것만):
- **수강생(입문자/비개발자)** - 이 단계 따라하다 어디서 막히나? 처음 보는 용어 설명 있나? 내가 **직접 칠 프롬프트/할 실습**이 있나, 아니면 화면만 보여주나("실습도 같이 있어야지")? 설명만 많고 "뭘 보고/칠지" 신호가 없나?
- **강사(라이브)** - 이 순서로 시간 안에 되나? 환경/권한 당일 붕괴 지점? 시연 -> 실습 흐름이 자연스럽나?
- **발주처(B2B)** - 우리 실제 업무 데이터/사례에 닿나? 약속한 성과에 연결되나?

규칙:
- **pre-emit 인용 게이트** - 모든 지적은 교안의 해당 줄(파일:줄 또는 인용)을 단다. **인용 못 하면 폐기**한다.
- 각 지적: `차원 | 인용 위치 | 문제 | 심각도 | 바꿀 내용`. 차원 정본은 아래 표.
- **false-positive 억제** - 이미 충분히 쉬운 설명을 "더 풀라", 원본 밀도 이내인데 "더 채우라"는 nitpick 금지(비대 유발).

## 3. 환각 차단 게이트 (page-id 실존/접근)

지적/반영에 적은 모든 page-id는 실존/접근 확인: 프로젝트 인증 절차로 `python3 curriculum_gate.py verify-pages <page-id> ...`를 실행한다. **401은 토큰 무효, 403은 권한/capability 부족, 404는 리소스 없음 또는 미공유**라서 404만으로 환각이라고 단정하지 않는다. 하나라도 미확인이면 반영하지 않는다.

## 4. 개선 = 실행 (제안에서 멈추지 않는다)

페르소나 발견 + 린트를 **실제로 고친다**. 약점 표로 끝내지 않는다. **단 개선은 명시적 결함(누락/오류/낡음/AI 티)만 외과적으로 - 멀쩡한 기존 자료를 AI 미감으로 재작성하지 않는다**(author-intent.md: 약간의 개선만, AI 판단 불신).

0. **소스 원문 정독** - 참조 소스를 요약본으로 대신하지 않는다. 원문을 재열람하고, 원문에는 있지만 교안에는 없는 디테일을 채택/기각과 사유로 기록한 뒤 채택분만 이식한다.
1. **텍스트** - 신호 없는 섹션에 복붙 프롬프트/실습 추가, slop/안심말 삭제, 설명 과잉을 핵심 신호로.
2. **이미지 - 실제로 확보한다**. 기존 검증 이미지와 공식 출처 이미지를 우선한다. 생성은 세상에 실물이 없는 net-new 산출물 결과 화면이나 목업에만 쓴다. 원본의 실제 스크린샷, 로고, 도식을 생성물로 대체하지 않는다.
3. **형제 클립 중복 스윕** - 병렬 개선 뒤 챕터/팩 단위로 새 블록의 중복을 검사하고, 뒤 클립은 상대 지칭 한 줄로 축약한다.
4. **증거(반영 전)** - `review-draft <교안.md>` 재실행으로 before/after를 확인하고, `verify-media <원본> <교안.md>`로 이식 이미지 누락을 검사한다. 새 산출물/도메인이면 `--require-new`로 이식 외 시각자료 1개 이상을 확인한다. 실제 산출물은 캡처하고, 아직 존재하지 않는 net-new 산출물만 결과 화면/목업을 생성한다. 반영 후 round-trip은 별도다.

## 5. iterate-until-pass (종료조건)

2 -> 4를 반복한다. **종료조건**: (a) `review-draft` 고신호 0 **AND** (b) 페르소나 비평이 2라운드 연속 material 발견 없음, **또는** (c) 사용자 만족. 보통 2~3라운드. 그래도 남으면 남은 약점을 정직하게 보고하고 사용자 판단을 받는다(무한 반복/혼자 단정 금지).
- **짧은 클립/이미 촬영된 회차는 단일 패스 허용** - review-draft 0이고 material 페르소나 발견이 없으면 1라운드로 종료. 라운드 수 채우려는 빈 반복은 금지(과한 절차도 비대다).

## 6. 검수 리포트 산출물 + 반영 (게이트)

- **검수 리포트** `검수-<회차>.md`를 남긴다. 상단에 `교안: <파일명>`, `후보: <파일명...>`, `교안 SHA256: <hash>`, 후보별 `후보 SHA256: <파일명>=<hash>`를 적어 현재 입력과 묶고, 라운드별 `페르소나 발견(인용) | 실제 바꾼 것 | review-draft/verify-media before->after`를 기록한다. 교안이나 후보가 바뀌면 해시를 다시 계산한다. binding이 틀리면 `gate-review`가 현재 필요한 해시 줄을 출력한다.
- **게이트(반영 전제)** - `python3 curriculum_gate.py gate-review --candidates curriculum-candidates-*.md --report 검수-<회차>.md <교안.md>`가 exit 0이어야 반영한다. 이 명령은 후보 검토, 리포트 형식, 고신호 smell 0, `format_scan` 0을 확인한다. 실제 개선 여부는 리포트 인용과 교안 diff를 별도로 확인한다.
- **반영(선택적 Phase 6)** - 프로젝트가 Notion 발행을 쓰고 사용자가 요청한 경우에만 진행한다. `notion_reflect.py`는 단일 page/md pair, 기대 title/parent/last-edited, 현재 candidates/report를 모두 검증한 뒤 update한다.

## 검수 차원과 정본 (재서술 금지, 포인터만)

| 차원 | 무엇을 보나 | 정본 |
|---|---|---|
| 논리 구조 | 고객/수강생 중심 사고 사슬인가 | authoring 도입부 |
| 신호/실습 | 수강생이 뭘 보고/칠지, 실습이 있나 | authoring 3-3절, 1절 린트 no-signal |
| 개념 명료성 | 정의->단계->프롬프트 리듬, 잡설 없나 | authoring 3-3절 |
| AI 티 표기 | 화살표/em dash/가운뎃점/섹션기호 | anti-patterns.md, 1절 린트 |
| 미디어 | 이미지 누락/출처/배치 | authoring 3-0절, verify-media |
| 안전선, 모순 | 내부 모순, 위험 명령 | SKILL 불변원칙 |
| 분량 | 원본 밀도 이내 | authoring 3-3절 |

## 실행 흐름

(단독은 0절 explore 먼저) -> review-draft 린트 -> 페르소나 비평(인용 게이트) -> verify-pages -> 실제 개선(텍스트+이미지) -> review-draft/verify-media before->after -> iterate(종료조건) -> 검수 리포트 -> 반영 -> round-trip.
