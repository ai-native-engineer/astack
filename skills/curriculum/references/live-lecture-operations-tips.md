# 라이브(실시간) 강의 운영 팁 - 살아있는 문서

> 시간이 정해진 **라이브 강의**(기업 교육, 워크숍, 오프라인 회차)를 진행할 때의 운영 노하우 모음. 영상 클립엔 대부분 불필요하다.
> **이 파일은 계속 유지보수한다.** 회차를 진행하며 새로 겪은 패턴, 실패, 해법을 맨 아래 "운영 로그"에 날짜와 함께 누적하고, 일반화되면 위 카테고리로 승격한다.
> 시드 출처: 고객사 B(8회차 진행중), 선엔지니어링 한 회차(Claude Desktop) 실전.

## 유지보수 규칙

- **추가**: 새 팁은 가장 가까운 카테고리(1~6절)에 한 줄로. 마땅한 데가 없으면 7절 운영 로그에 `YYYY-MM-DD - [상황] -> [해법]`으로.
- **승격**: 7절 로그에서 2회 이상 반복 확인된 항목은 위 카테고리로 올리고 로그엔 날짜만 남긴다.
- **정리**: 특정 도구/고객에만 해당하는 건 프로젝트 `AGENTS.md`로 내린다. 여긴 **여러 강의에 공통**인 것만.
- 잔여물 금지: 더 이상 안 맞는 팁은 지운다(처음부터 그렇게 쓴 것처럼 읽혀야 함).

## 1. 시간 관리 - "계획대로 안 끝나는 게 정상"

- **회차 이월(carry-over)**: 시간 초과분은 다음 회차 도입부에 "지난 시간에 못한 X부터 이어서"로 명시하고, `curriculum-v{N}` 변경이력에 기록한다. 이월을 숨기지 말고 설계의 일부로.
- **전원 사수선**: 실습 슬롯마다 "전원이 최소 여기까지는 한다"는 한 줄 목표를 정한다(예: "gog로 시트 1개 읽기"). 그 위는 보너스.
- **라벨링**: 각 실습을 `(강사 데모)` / `(전원 실습)`으로 미리 표시. 난이도 높은 건 데모로 돌리고 전원 실습은 사수선만.
- **데모 압축**: 한 블록에 풀코스 금지. 데모는 "완성본 먼저 -> 한 부분만 라이브 수정 -> 배포/마무리는 준비된 환경에서 빠르게."
- **쿠션/보너스 카드**: 응답 대기, 진도 빠름, 시간 초과 대비로 **생략 가능한 보너스 모듈**을 1~2개 준비. 시간 남으면 풀고 모자라면 버린다.

## 2. 환경, 권한 - 당일 붕괴 1순위

- **사전 리허설 게이트**: 난이도와 별개로 **환경(사내망, 방화벽, 관리자 권한)**이 막히면 당일 붕괴. 회차 전 반드시 선검증 - 사내망에서 클라우드 DB/외부 API 접속 되는지, 확장 설치, 마켓플레이스 접근 되는지, 표준 PC 세팅(Node 등) 배포됐는지.
- **엔터프라이즈 권한 선결**: 학습자가 직접 못 따는 권한(관리자 승인, Domain-Wide Delegation, 서비스 계정 등)은 **"강사가 IT와 미리 선세팅 + 학습자는 인증 완료된 환경에서 조회만"**으로 재설계한다. "도구로 우회하면 권한이 쉬워진다"는 착각 금지 - 선결과제(주체, 일정, 선검증)를 커리큘럼 열린 항목으로 트래킹.
- **공용 vs 개별 세팅**: 참가자별 프로젝트(각자 키)인지 공용 프로젝트인지 사전 합의. 비개발자 다수면 공용 + 사전 배포가 안전.

## 3. 진행 자료 - 학습자용과 강사용 분리

- **강사 큐시트**: 진행 큐시트(타이밍, 전환 멘트, 데모 순서, 예상 막힘)는 학습자 노션 자료와 **별도 산출물**로 둔다. 학습자 본문엔 넣지 않는다.
- **위험, 보안 우회 명령**: 인증서 검증 끄기 같은 명령은 학습자, 강사 자료 어디에도 넣지 않는다(처리는 4절 막힘 대처).
- **스코프, 책임 가드**: 도구가 못 하는 범위를 실습마다 콜아웃으로 미리 좁힌다(전체 자동화 약속 금지).

## 4. 막힘 대처 - 한 가지로 일원화

- 학습자 막힘 대처는 **"에러 화면(또는 상황) 복사 -> AI에게"** 하나로 통일. 도구 내부를 직접 조작하라고 강요하지 않는다.
- 표준 디버깅 3단계: 1. 에러 메시지 그대로 복사해 "왜 이래? 해결해줘" -> 2. 에러 없이 안 움직이면 상황을 구체적으로 설명 -> 3. 그래도 안 되면 "어디서 막히는지 단계마다 로그를 찍어서 확인해줘."
- **환경, 설정, 인증서 에러도 예외 없이 이 흐름으로.** 우회 명령(인증서 검증 끄기 등)을 학습자, 강사 자료 어디에도 박지 않는다 - 에러 화면 복사 -> AI, 안 풀리면 강사/사내 IT가 직접 푼다.

## 5. Windows 수강생 (다수가 Windows일 때)

- `npm` 명령이 "스크립트를 실행할 수 없으므로…"로 막힘 -> PowerShell에 `Set-ExecutionPolicy RemoteSigned`(표준 실행 정책 설정).
- 배포 명령은 PowerShell이 아닌 CMD(명령 프롬프트)에서.
- 인증서 등 그 외 환경 에러는 **우회 명령을 적지 말고 4절 막힘 대처로**.

## 6. 비개발자 눈높이 (라이브에서 특히)

- 용어 첫 등장 1줄 풀이. 톤 "완벽하지 않아도 됨/할 수 있는 만큼", 존댓말, 부담 낮게.
- **개인 실습 목표는 1개 고정.** 욕심내지 말고 본인 결과물을 한 단계만 전진. 막힌 곳은 한 명씩 같이, 한 명도 빠짐없이(아웃풋 케어).
- 예시, 데모는 가능하면 **수강생 실제 업무**에서. 만족도, 니즈가 갈리면 사전 설문으로 개인별 케어 우선순위를 잡는다.
