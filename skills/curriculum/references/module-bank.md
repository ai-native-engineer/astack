# 모듈 뱅크 - 회차 자료를 모듈로 분해, 적재 (curriculum 스킬)

`강의 모듈` DB(재사용 모듈 뱅크)를 채우고 유지하는 절차. 반대 방향(모듈 -> 회차 조립)은 `authoring.md` 3-0절이 정본이라 여기서 반복하지 않는다.

DB 좌표(workspace id, db id, data-source id)는 프로젝트 `AGENTS.md`에 둔다(조직별로 달라 스킬에 박지 않음, notion-sync 4-2절). 속성 옵션의 정본은 DB 자체 - 아래 표의 값은 의미 설명용이고, 나열이 DB와 갈리면 DB를 따른다.

## 언제 적재하나
- 모듈 뱅크가 비었거나, 기존 회차 자료에 뱅크에 없는 검증된 설명/실습이 있을 때.
- 신규 회차 제작을 마친 뒤, 재사용 가치가 있는 블록을 모듈로 환류할 때.

**적재는 사용자 승인 후에만.** DB는 사용자가 큐레이션하므로 임의로 행을 추가하지 않는다. 강의자료 워크스페이스/조직 노션 전수에서 가져와 새로 조립한 검증 블록은, 작성을 마친 뒤 사용자에게 "이 모듈을 `강의 모듈` DB에 적재할까요?"를 물어 환류한다(authoring 3-0 환류 질문과 같은 트리거).

## 모듈 단위 - 무엇을 한 행으로
- 한 모듈 = 재사용 가능한 **개념 1개 또는 실습 1개** 블록. 회차 하나가 아니라 회차의 부품이다.
- 쪼개는 기준: 다른 회차나 다른 고객사에서 그 블록만 떼어 다시 쓸 수 있으면 한 모듈. 그 회차에서만 의미가 있으면 쪼개지 않는다.
- 한 문단 수준으로 잘게 쪼개지 않는다 - 떼어 가르칠 수 있는 최소 단위가 하한선이다.

## 분해, 적재 절차
1. 원본 회차를 `ntn pages get <page-id>`로 뜬다(공개 미러 `*.notion.site` 크롤 금지, 내부 원본 ntn).
2. 재사용 가능한 개념/실습 블록을 식별한다(위 단위 기준).
3. 블록마다 원본 흐름, 프롬프트, 이미지 ref를 보존해 모듈 본문을 만든다(이식, 미디어 보존 규칙은 `authoring.md` 3-0절, `image-generation-notion-assets.md`가 정본).
4. 아래 6개 속성을 채운다.
5. `ntn`으로 data-source에 행을 추가한다(data-source-id는 `AGENTS.md`). 적재 직후 round-trip으로 속성값과 본문 보존을 확인한다.

## 속성 계약 (6개 - 값은 DB 현재 옵션을 따른다)
| 속성 | 타입 | 채우는 법 |
|---|---|---|
| Name | title | 모듈명. "주제: 무엇" 형식 (예: "크롤링 개념: 정적, 동적 페이지 차이") |
| 유형 | select | 블록 성격 하나: 도입/개념/시연/실습/프로젝트/정리/환경설정 |
| 주제 | multi_select | 해당하는 대분류 (DB 옵션 15종 중) |
| 도구 | multi_select | 그 블록에서 실제 쓰는 도구만 (DB 옵션 중, 없으면 비움) |
| 모듈 설명 | rich_text | 한 줄 학습목표 - 수강생이 무엇을 할 수 있게 되는가 |
| 원본 출처 | rich_text | 어느 회차, 페이지에서 왔는지 (추적용, 예: "고객사 A 3회차") |

## 게이트
- 적재를 "추가했다"로 단정하지 않는다. data-source query로 행 실재와 속성값을 확인한 산출물로만 완료를 단정한다(#7 처방).
- 원본 미디어 ref는 전수 보존한다(누락 0). 텍스트만 옮기지 않는다.
