# 이미지 소싱, 생성, Notion 자산 반영

강의 자료의 이미지를 고르고, 필요한 경우 생성하고, 선택적으로 Notion에 반영하는 절차다. 인증과 공통 파일/API 명령은 `notion` 스킬의 `references/ntn-cli.md`가 정본이다. 해당 스킬이나 `ntn`이 없으면 Notion 반영을 실행하지 않는다.

## 목차

- 이미지 출처 우선순위
- 1. 자산 유형 구분
- 2. Notion 삽입
- 3. 반영 후 검증
- 4. 생성 규칙
- 5. net-new 결과 화면/목업 프롬프트

## 이미지 출처 우선순위

위에서부터 시도한다.

1. **기존 검증 자료 이식**: 원본의 실제 스크린샷, 로고, 도식, caption, `file://` ref를 보존한다.
2. **공식 출처 이미지**: 공식 문서, 제품 사이트, 공식 발표에서 본문과 직접 관련된 이미지나 차트를 고른다.
3. **실제 화면 캡처**: 공식 이미지가 없을 때 로그인 없이 재현 가능한 화면이나 직접 만든 산출물을 캡처한다.
4. **이미지 생성**: 세상에 실물이 없는 이번 회차의 **net-new 산출물 결과 화면이나 목업**에만 쓴다.

개념 설명 이미지는 1~3에서 찾는다. 기존 제품 UI는 공식 이미지가 먼저고, 없으면 실제 화면을 캡처한다. 공식 이미지라도 본문과 무관하면 넣지 않는다.

## 1. 자산 유형 구분

### 기존 Notion 이미지

- 원본 `file://` attachment ref를 사용할 수 있으면 그대로 이식한다.
- `pages get`이 내보낸 만료 presigned S3 URL은 로컬 본문에 다시 넣지 않는다.
- 원본 ref를 쓸 수 없으면 이미지를 내려받아 프로젝트 자산으로 보관한 뒤 새 로컬 이미지 절차를 따른다.

### 새 로컬 이미지

- 프로젝트 `output/assets/` 또는 프로젝트가 정한 자산 폴더에 최종본을 둔다.
- 로컬 절대경로나 상대경로를 그대로 `pages update`하면 Notion에서 빈 이미지가 될 수 있다.
- 본문 update 전에 Notion file upload id를 확보하고 image block으로 삽입할 수 있어야 한다.

### 생성 이미지

- 기존/공식 이미지와 실제 캡처로 해결되지 않는 net-new 결과 화면/목업만 생성한다.
- 현재 런타임이 제공하는 공식 이미지 생성 도구를 쓴다.
- 생성 결과를 프로젝트 자산 폴더에 저장하고 직접 열어 검수한다.

## 2. Notion 삽입

공통 쓰기 승인과 페이지 백업을 먼저 수행한다.

1. 파일 업로드 도구가 안정적인 upload id를 반환하는지 **본문 update 전에** 확인한다.
2. upload id를 확보하면 image block을 구성한다.
3. 이미지 바로 앞의 실제 텍스트 block id와 실제 부모를 조회한다.
4. `position.after_block`으로 image block을 삽입한다.
5. 삽입 직후 블록 위치와 개수를 round-trip으로 확인한다.

현재 `notion_reflect.py`는 로컬 이미지가 있을 때 upload id 계약을 사전 검증한다. `ntn` 출력에서 upload id를 얻지 못하면 fail-closed로 본문 update를 거부한다. 이 경우 다음 중 하나를 선택한다.

- upload id를 보장하는 도구로 파일을 업로드한다.
- Notion에서 파일을 수동 업로드한 뒤 block id를 확인해 surgical 삽입한다.
- 이미지가 포함된 전체교체를 중단하고 텍스트와 이미지를 각각 승인받아 반영한다.

외부 공개 URL을 image block의 영구 저장소로 가정하지 않는다. 장기 보존이 필요하면 파일을 내려받아 Notion 파일로 업로드한다.

## 3. 반영 후 검증

- 이미지가 의도한 섹션과 앵커 다음에 있음
- 기대한 신규 이미지 수와 실제 image block 수가 일치
- 기존 이미지/GIF/첨부가 보존됨
- 빈 이미지 `![]()` 0
- staging/test 링크 0
- 이미지가 설명보다 먼저 나오고, 주변 본문이 핵심을 설명함
- 공식 이미지 출처가 섹션 하단 북마크 카드로 연결됨

전체 페이지 검증은 [`notion-sync.md`](notion-sync.md) 4-3절을 따른다.

## 4. 생성 규칙

- 생성 대상은 net-new 산출물 결과 화면, 목업, 아직 존재하지 않는 흐름의 시각화로 제한한다.
- 기존 제품 UI, 실제 로고, 공식 다이어그램을 비슷하게 재생성하지 않는다.
- 브랜드가 필요하면 공식 로고 파일을 레퍼런스로 전달한다. 검증할 수 없으면 로고를 빼고 일반 UI 구조로 만든다.
- 기본 톤은 프로젝트의 기존 강의 이미지다. 기존 톤이 없으면 밝은 문서형 B2B 톤을 쓴다.
- 이미지 안 텍스트는 짧은 제목과 라벨로 제한한다.
- 한글은 확대해 직접 읽고 한 글자라도 틀리면 텍스트를 줄여 다시 생성한다.
- SVG, HTML/CSS 렌더링, 수동 텍스트 오버레이로 생성 결과를 보정하지 않는다.
- 같은 페이지 안 중복만 제거한다. 서로 독립적으로 보는 여러 페이지에는 필요한 이미지를 각각 둔다.
- 이미지 아래 캡션식 설명을 반복하지 않는다. 설명은 본문 흐름에 둔다.

## 5. net-new 결과 화면/목업 프롬프트

```text
강의 자료용 16:9 결과 화면 목업을 만들어주세요.

대상:
[이번 회차에서 새로 만드는 산출물]

수강생이 확인해야 할 결과:
- [핵심 결과 1]
- [핵심 결과 2]
- [선택확장 결과, 없으면 삭제]

구성:
- 실제 업무 도구처럼 보이는 현실적인 화면
- 본문에서 설명하는 정보 구조와 상태가 보이게
- 밝은 문서형 배경과 읽기 쉬운 위계
- 필요한 짧은 한글 라벨만 정확하게

금지:
- 기존 제품 UI나 로고를 임의 재현
- 장식용 추상 일러스트
- 본문에 없는 기능이나 수치 추가
- 긴 설명 문장
```
