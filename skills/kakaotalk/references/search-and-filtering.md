# 검색과 결과 좁히기

## 목차

- 검색 방식 고르기
- keyword 검색의 실제 동작 - limit을 넉넉히 준다
- 질의 비용과 병렬 실행
- 기간으로 좁히기 - CLI에 날짜 필터가 없다
- 발신자로 좁히기 - CLI에 발신자 필터가 없다
- 내가 한 말 찾기 - 본인 닉네임 확정
- 본문 회수 - chunks에는 본문이 없다

## 검색 방식 고르기

| 언제 | 명령 |
|---|---|
| 문자열을 정확히 안다 | `katok search keyword` |
| 여러 단어로 관련도 순위가 필요하다 | `katok search bm25` |
| 표현이 불확실하고 의미로 찾는다 | `katok search semantic` |

semantic은 벡터 인덱스가 필요하다. `katok doctor --json`의 `freshness.last_index.embedded_texts`가 `0`이거나 최근 sync 내용까지 의미 검색해야 하면 소요 가능성을 알린 뒤 `katok index --json`을 먼저 실행한다.

## keyword 검색의 실제 동작 - limit을 넉넉히 준다

`keyword`는 부분 문자열 일치이고, 결과를 **오래된 순으로 정렬한 뒤 limit에서 자른다**. 관련도 순이 아니다.

- 작은 limit은 최신 결과가 아니라 **가장 오래된 결과**를 준다. "최근에 뭐라고 했지"에 몇 년 전 대화가 나오는 원인이다.
- limit은 최대 100000까지 받는다. 전량을 받고 클라이언트에서 좁히는 것을 기본으로 한다.
- 부분 문자열이므로 어미를 짧게 자르면 회수가 올라간다. `할게`는 `할게요`를 포함하고, `게요`는 `보낼게요`, `정리할게요`, `알려드릴게요`를 한 번에 잡는다.

```bash
katok search keyword "게요" --limit 100000 --json > hits.json
```

## 질의 비용과 병렬 실행

한 질의가 아카이브 전체를 훑는다. 대형 아카이브에서는 질의당 수십 초가 든다.

- 표현을 여러 개 훑을 때는 순차로 돌리지 말고 병렬로 던진다.
- 표현 목록은 어미 계열(`게요`, `할게`, `드릴게`, `겠습니다`, `께요`)과 의도 계열(`하기로`, `약속`, `예정`)을 섞는다. 어미 하나로는 의문형 약속(`전달 드려도 될까요?`)을 놓친다.

```bash
printf '%s\n' 게요 할게 드릴게 겠습니다 께요 하기로 약속 예정 \
  | xargs -P 5 -I{} sh -c 'katok search keyword "{}" --limit 100000 --json > "q_{}.json"'
```

## 기간으로 좁히기 - CLI에 날짜 필터가 없다

검색과 목록 명령에는 기간 옵션이 없다. 결과의 `started_at`으로 직접 거른다.

- `started_at`은 **UTC**다. "이번 달", "오늘" 같은 한국 기준 경계는 9시간을 빼서 계산한다.
- KST 2026-08-01 00:00은 `2026-07-31T15:00:00`이다.

```bash
jq -s '[.[][]] | unique_by(.chunk_id)
  | map(select(.started_at >= "2026-07-31T15:00:00"))' q_*.json
```

## 발신자로 좁히기 - CLI에 발신자 필터가 없다

결과의 `sender_nickname`으로 거른다. chunk는 발신자가 바뀌면 분리되므로 한 chunk에 두 사람이 섞이지 않는다.

```bash
jq 'map(select(.sender_nickname == "<이름>"))'
```

## 내가 한 말 찾기 - 본인 닉네임 확정

본인 메시지에는 별도 플래그가 없다. **본인의 카카오톡 표시 이름이 그대로** 들어가고, 사용자 정보를 못 읽었을 때만 `나`로 들어간다. 즉 이름을 먼저 확정해야 한다.

사용자에게 표시 이름을 물어도 되고, 모르면 아래 두 단계로 확정한다.

1. 넓은 검색 결과에서 **등장하는 방 개수가 가장 많은 발신자**를 고른다. 본인은 모든 방에 있고 다른 사람은 일부 방에만 있다.
2. 그 이름이 1:1 방 이름 목록에 **없는지** 확인한다. 1:1 방은 상대방 이름으로 명명되고 계정 소유자 이름으로는 명명되지 않으므로, 방 이름에 없으면서 방 개수 1위면 본인이다.

```bash
# 1단계: 방 개수 기준 상위 발신자
jq -r '.[] | [.sender_nickname, .chat_name] | @tsv' hits.json \
  | sort -u | cut -f1 | sort | uniq -c | sort -rn | head

# 2단계: 1:1 방 이름과 대조 (0이면 본인)
katok source chats --source macos --json | jq -r '.[].chat_name' | grep -c "<후보 이름>"
```

확정이 애매하면 1:1 방 하나를 골라 8월 chunk의 발신자가 두 사람으로 갈리는지 본다. 갈리면 귀속이 정상이다.

## 본문 회수 - chunks에는 본문이 없다

`katok chunks --chat <id>`는 메타데이터만 준다. `text` 필드가 없으므로 이 출력만으로는 대화를 읽을 수 없다.

- 대화를 읽으려면 chunk id를 골라 `katok chunk get <chunk-id> --json`으로 본문을 받는다.
- `katok chunks --chat`은 그 방의 **전 기간**을 반환하고 호출마다 비싸다. 모든 방을 순회해 기간을 좁히는 방식은 쓰지 않는다. 기간을 좁힐 때는 검색 결과를 거르는 쪽이 훨씬 싸다.

## 결과에 섞이는 노이즈

- parent window 단위로 잡힌 결과는 `sender_nickname`이 `multiple`이다. 발신자 필터에 그대로 걸리지 않으니 별도로 처리한다.
- 자동화가 보낸 메시지도 본인 발화로 잡힌다. 뉴스 요약이나 알림 봇을 본인 계정으로 보내고 있으면 "내가 한 말" 집계에서 뺀다.
- 통화 초대나 선물 알림 같은 시스템 메시지는 JSON 덩어리로 들어온다. 사람이 쓴 문장만 필요하면 걸러낸다.
