# Search And Apply

레시피가 없을 때만 읽는다. 공식 API와 스키마를 찾고, 호출 가능 여부를 확인한다.

## 검색 순서

1. `references/provider-routing.md`로 provider 후보를 좁힌다.
2. provider 파일의 공식 포털·문서 위치를 연다.
3. 데이터명보다 기관명 + 업무명으로 검색한다.
4. 0건이면 동의어, 법인명 변형, 영문명, 옛 이름으로 2~3회 재검색한다.
5. 후보가 여럿이면 공식성, 최신성, 신청 가능 여부, 필드 충분성을 기준으로 고른다.

## 스키마 확보

레시피에 남길 만큼만 추출한다.

- 공식 API명
- 문서 또는 상세 페이지 URL
- endpoint base와 operation
- 필수 파라미터
- 응답 핵심 필드
- 페이징 방식
- 에러 코드 또는 미승인 응답

전체 API 카탈로그를 SKILL.md나 provider 파일에 복사하지 않는다. 공식 문서가 정본이다.

## 신청이 필요한 경우

- 사용자가 신청까지 요청한 경우 공식 form에서 서비스명, 권한 범위, 활용 목적, 적용 URL, 서버 IP, 동의 항목을 확인하고 제출한다.
- 제출 결과와 확인 위치만 기록한다. 키, 쿠키, 개인정보, 공인 IP 원문은 레시피·로그·보고서에 저장하지 않는다.
- 신청 직후 실패는 키 동기화 지연일 수 있으므로 즉시~1시간 재시도 가능성을 안내한다.

## 실패 보고

"API 없음" 대신 아래처럼 구분한다.

- 공식 API 검색 결과 없음
- API는 있으나 신청/승인 필요
- API는 있으나 스키마 확보 실패
- API는 있으나 호출 결과 0건
- 다운로드/웹 조회만 있고 Open API는 확인 못함
