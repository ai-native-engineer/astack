# Call Patterns

provider 파일을 읽은 뒤 호출 직전에 적용한다.

## 키 처리

1. 가능하면 `agents-env run <KEY_NAME> -- <명령>`으로 주입한다.
2. 안 되면 환경변수 `<KEY_NAME>`을 확인한다.
3. 그래도 없으면 cwd `.env`를 확인한다.
4. 셋 다 없으면 발급·등록 위치를 안내하고, 실제 키 없이 호출 성공을 주장하지 않는다.

키 평문은 명령 출력, 레시피, 로그에 남기지 않는다. 레시피에는 `$KEY_NAME` 또는 `{{KEY_NAME}}`만 쓴다.

## 호출

- GET 쿼리는 `curl -sG`와 `--data-urlencode`를 우선 쓴다.
- 이미 인코딩된 키를 다시 urlencode하면 실패할 수 있다. provider별 인코딩 규칙을 먼저 확인한다.
- JSON/XML 응답 형식 파라미터는 provider마다 다르므로 레시피에 실제 값을 적는다.
- 첫 페이지만 보고 전체라고 말하지 않는다. `totalCount`, `page`, `numOfRows`, cursor 유무를 확인한다.

## 에러 판독

| 증상 | 해석 | 행동 |
|---|---|---|
| 키 오류·미등록 | 키 이름, 인코딩, 동기화 문제 | 키 소스와 인코딩을 다시 확인 |
| 접근 거부·미승인 | API 또는 서비스 활용신청 필요 | 활용신청/승인 상태와 키 발급 여부를 확인 |
| 쿼터 초과 | 일일/월간 제한 | 운영 키 또는 재시도 시점 안내 |
| 정상 코드 + 0건 | 조건 불일치일 수 있음 | 이름·기간·식별자를 바꿔 재조회 |
| 스키마 불일치 | API 개편 또는 레시피 노후화 | 공식 문서를 다시 확인하고 레시피 갱신 |

## 저장 기준

성공 레시피는 재현 가능한 최소 호출이어야 한다.

- checked 날짜
- provider
- endpoint 또는 공식 문서 위치
- 필수 파라미터
- 응답 핵심 필드
- 페이징 방식
- provider/API 고유 함정
