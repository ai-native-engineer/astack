# 화자 분리

화자 분리 모드에서는 MOSS-Transcribe-Diarize가 글과 화자를 함께 만든다. 이 모드의
텍스트 정본은 MOSS이고, Apple 결과로 빈 곳을 채우거나 MOSS 텍스트를 고치지 않는다.
pyannote Community-1은 자를 위치와 조각 사이 화자 잇기에만 쓴다. 모두 로컬에서 실행한다.

## 목차

- 실행: 명령, 출력 파일, 환경 변수
- 준비와 종료 코드: 모델 캐시, 실패 때 할 일
- 흐름: 자르기, MOSS, 화자 잇기, 빈 곳
- 결합 규칙: 턴 묶기, 1인 녹음, 빈 곳 표시
- 확인 화면: 듣고 이름 붙이기
- 목소리 기억: 등록, 찾기, 기준값
- 함정: 용어 힌트, mlx-audio 버전
- 근거
- 구간 선택

## 실행

설치된 `stt` 스킬 루트에서 실행한다.

```sh
bash scripts/stt_diarize.sh <오디오> [start초] [end초]
```

결과는 `stt/YYMMDD-HHMMSS-PID/` 아래에 생긴다.

- `diarized.md`: 사람이 읽는 화자별 턴
- `transcript.json`: MOSS 구간마다 시작, 끝, 전역 화자, 조각 번호, 조각 안 화자, 텍스트. `gaps`에 빈 곳 목록
- `diar.rttm`: MOSS 구간을 전역 화자로 적은 RTTM
- `speakers.json`: 전역 화자마다 말한 시간과 목소리 특징값(목소리 기억 참고)
- `names.json`: 기억한 목소리에서 찾았거나 확인 화면에서 붙인 이름
- `run.json`: 확인 화면이 읽는 원본 오디오 경로와 구간 시작 시간

구간 시작값을 주면 `diarized.md`의 시간은 원본 녹음 기준이고, `transcript.json`과
`diar.rttm`은 잘린 구간 기준 시간을 그대로 둔다.

환경 변수:

- `PYANNOTE_PYTHON`: pyannote가 설치된 Python. 기본은 `uv tool`로 설치한 `whispermlx`의 Python
- `PYANNOTE_DEVICE`: `auto`(기본), `mps`, `cpu`
- `MOSS_PYTHON`: mlx-audio가 설치된 Python. 기본은 `uv run`으로 만드는 mlx-audio 0.5.9 환경
- `MOSS_MODEL`: MOSS 모델 ID. 기본은 `OpenMOSS-Team/MOSS-Transcribe-Diarize`
- `STT_OUT`: 출력 루트
- `STT_VOICES`: 기억한 목소리 저장소 경로. 기본은 `~/.local/share/stt/voices.json`

## 준비와 종료 코드

두 모델은 Hugging Face 캐시에 미리 받아 둔다. 실행 중에는 모델을 내려받거나 오디오를
밖으로 보내지 않는다. mlx-audio 환경은 첫 실행 때 `uv`가 패키지를 받아 만든다.

```sh
hf download OpenMOSS-Team/MOSS-Transcribe-Diarize
hf download pyannote/speaker-diarization-community-1
```

- 64: 인자가 잘못됨
- 66: 오디오 파일이 없음
- 69: 런타임이나 모델 캐시가 준비되지 않음. 전사를 시작하기 전에 멈춘다
- 70: MOSS나 pyannote 단계가 실패함

MOSS가 실패하면 Apple 결과로 대신 만들지 않는다. 실패를 사용자에게 알리고, 화자 없이
글만 필요하면 빠른 전사(`scripts/stt-fallback.sh`)를 제안한다.

## 흐름

1. ffmpeg로 16kHz 모노 WAV를 만든다.
2. `pyannote-chunks.py plan`이 pyannote 분할 모델만 돌려 말이 있는 곳을 찾는다.
   10분마다 자르되, 목표 지점 앞뒤 90초 안의 가장 긴 쉼에서 자른다. 마지막 조각은
   15분까지 늘려 짧은 꼬리를 만들지 않으므로 15분 이하 녹음은 조각 하나다.
   소리 크기만 보는 방식은 말하는 도중에 자르는 경우가 많아 쓰지 않는다.
3. `moss-diarize.py`가 모델을 한 번 불러 조각마다 MOSS를 돌린다. 조각 안 화자는
   S01, S02처럼 조각마다 새로 번호가 붙는다. 조각을 나누는 이유는 메모리다. 10분 조각은
   약 4GB에서 머물지만, 한 시간 넘는 녹음을 한 번에 넣으면 메모리와 시간이 크게 는다.
4. `pyannote-chunks.py join`이 조각 사이 화자를 잇는다.
    - 1초 이상인 MOSS 구간마다 Community-1의 화자 특징값을 뽑는다. 20초가 넘는 구간은 가운데 20초만 쓴다.
    - 조각 안 화자마다 구간 길이로 가중한 평균 방향을 만든다.
    - 평균 연결 방식으로 코사인 유사도 0.62 이상인 화자끼리 합친다.
    - 같은 조각의 두 화자도 합칠 수 있다. MOSS가 한 사람에게 라벨 두 개를 붙이는 경우가 있다.
    - 특징값이 있는 말이 5초 미만인 조각 화자는 비교하지 않고 따로 라벨을 받는다.
    - `SPEAKER_00`은 가장 오래 말한 사람이다.
5. 말소리가 있는데 MOSS 구간이 10초 넘게 없는 곳을 `gaps`로 남긴다.
6. `voices.py match`가 기억한 목소리를 찾아 `names.json`을 쓴다.
7. `diar_views.py`가 `diarized.md`를 만든다.

## 결합 규칙

- 같은 화자의 구간이 이어지면 한 턴으로 묶고, 턴의 첫 구간 시작 시간을 표시한다.
- 화자가 한 명만 잡히면(`?` 제외) 2초 이상 쉬거나 턴이 60초를 넘을 때 새 턴을 연다.
  강의처럼 한 사람이 말하는 녹음이 한 문단으로 뭉치지 않게 하려는 것이고, 값은 Alt
  앱의 1인 턴 규칙과 같다. 화자가 둘 이상이면 이 규칙을 쓰지 않는다.
- 빈 곳은 시간 순서대로 `**[gap]** (시작~끝)` 줄로 넣는다. 전사본을 넘길 때 글이
  빠졌을 수 있는 구간으로 함께 알린다. Apple로 빈 곳을 채우지 않는다. 행사장 주변
  소리처럼 MOSS가 비운 것이 맞는 경우가 많고, Apple이 채운 글은 대부분 짧은 조각이었다.
- 텍스트를 바꾸거나 빼지 않는다.
- 화자 이름은 사용자가 확인 화면에서 붙였거나 기억시킨 목소리에서만 온다.
- 같은 이름이 붙은 화자 둘은 한 사람으로 보고 이어진 턴을 합친다. 목소리가 비슷하지
  않아 화자 잇기가 한 사람을 둘로 나눈 경우를 사용자가 이름으로 바로잡는 방법이다.

## 확인 화면

사용자가 결과를 들으며 확인하거나 화자에게 이름을 붙이려 하면 확인 화면을 연다.

```sh
python3 scripts/diar_review.py <결과 폴더>
```

- 백그라운드로 실행하고 출력된 `http://127.0.0.1:...` 주소를 사용자에게 알린다.
  기본 브라우저에서 저절로 열린다.
- 화면에서 할 수 있는 일: 시간을 눌러 그 턴부터 듣기, 화자별 목소리 듣기, 이름
  저장, 추정 이름 확인, 이 녹음에서 이름 지우기, 기억한 목소리 잊기.
- 이름을 저장하면 그 결과 폴더의 `names.json`과 `diarized.md`가 바로 바뀐다.
  "다음 녹음에서도 알아보기"를 켜 두면 `voices.py enroll`과 같은 등록도 한다.
- 화면의 턴 목록에는 빈 곳 줄을 넣지 않는다. `diarized.md`에는 그대로 남는다.
- 서버는 `127.0.0.1`에만 열리고, 주소에 든 토큰이 없는 요청은 거절한다.
- 탭을 닫으면 10분 뒤 서버가 스스로 꺼진다. 다시 열려면 같은 명령을 실행한다.
- 원본 오디오를 옮겼으면 `--audio <경로>`로 알려 준다. 오디오가 없어도 이름
  저장은 된다.

## 목소리 기억

사용자가 이름을 알려 준 화자만 기억하고, 다음 녹음에서 그 목소리를 찾아 이름으로
표시한다. 목소리 특징(embedding)은 생체 정보이고 녹음에 나온 다른 사람의 것이기도 하다.

```sh
python3 scripts/voices.py enroll <결과 폴더> SPEAKER_01 <이름>
python3 scripts/voices.py list
python3 scripts/voices.py forget <이름>
```

- 등록: 사용자가 확인 화면에서 "알아보기"를 켠 채 이름을 저장하거나, 대화에서
  그 사람을 기억하라고 할 때만 등록한다. 전사본에 이름이 나왔다는 이유만으로
  등록하지 않는다. 말한 시간이 3초 미만인 화자는 등록하지 않는다.
- 저장소는 소유자만 읽는다(0600). 밖으로 보내지 않는다. 이름 하나에 샘플을
  15개까지 두고, 넘치면 가장 짧은 샘플부터 지운다. `forget`은 그 이름의 샘플을
  모두 지운다.
- 결과 폴더의 `speakers.json`에는 그 녹음에 나온 모든 화자의 특징이 들어 있다.
  화자 잇기 단계에서 사람마다 구간 특징값을 길이로 가중 평균한 값이다. 등록할 때
  읽는 원본이고, 결과 폴더를 지우면 함께 사라진다.
- `voices.py enroll`은 다음 실행부터 적용되고 이미 만든 `diarized.md`는 바꾸지
  않는다. 지금 전사본에도 이름을 붙이려면 확인 화면에서 저장한다.
- 찾기: `stt_diarize.sh`가 실행마다 `voices.py match`를 부른다. 이름마다 가장
  비슷한 샘플 3개의 코사인 유사도를 말한 길이(60초 상한)로 가중 평균한다. Alt
  앱의 화자 갤러리와 같은 계산이다.
    - 0.70 이상이고 다음 후보 이름보다 0.1 이상 높으면 이름으로 표시한다.
    - 0.60 이상 0.70 미만이면 `SPEAKER_01 민지?`처럼 추정으로 표시한다. 전사본을
      넘길 때 확인 대상으로 함께 적는다.
    - 그 밖이거나 말한 시간이 3초 미만이면 익명 라벨 그대로다.
    - 한 이름은 한 녹음에서 화자 한 명에게만 붙는다.
- 기준값 근거: 등록에 쓰지 않은 녹음 5개에서 등록한 사람은 0.84~0.89, 나머지
  화자는 모두 0.49 이하였다. pyannote 전체 실행의 특징값으로 잰 녹음 12개에서도
  같은 녹음 안의 서로 다른 화자 쌍이 0.58까지 올라갔다. Alt 앱 값(추정 0.45,
  자동 0.6)을 그대로 쓰면 다른 사람이 같은 이름을 받는다. 화자 특징값을 만드는
  방식을 바꾸면 기준값을 다시 잰다.

## 함정

- MOSS에는 용어 힌트를 넣지 않는다. 지시문 뒤에 용어 목록을 붙여도 고쳐지는 용어는
  없었고, 없던 말이 생겼다.
- mlx-audio의 `generate(hotwords=...)`를 prompt 없이 부르면 용어 목록이 기본 지시문을
  대신해, 시간과 화자 형식이 사라지고 구간 하나, 화자 하나로 깨진다.
- mlx-audio 버전을 올리면 MOSS 출력 파싱(구간의 `speaker_id`, 텍스트 앞 `[S01]`)부터
  다시 확인한다.

## 근거

2인 대화 3분 녹음을 사람이 듣고 고른 16개 구간에서 화자까지 따진 글자 오류율(cpCER)은
MOSS 0.018, Apple 단어와 pyannote 결합 0.521, Whisper와 pyannote 결합 0.516이었다.
화자 잇기 기준값 0.62는 긴 녹음 세 개에서 뽑았다. 같은 사람 짝의 유사도 중앙값은 0.95,
다른 사람 짝은 0.31이었다. 목소리 잇기와 pyannote 전체 실행 잇기가 엇갈린 곳을 들어 보면
목소리 쪽이 더 자주 맞았다. 목소리가 비슷한 두 사람을 한 사람으로 묶는 틀림은 남는다.

## 구간 선택

회의 뒤 이동, 음악, 긴 잡음이 붙은 녹음은 가짜 화자 수를 늘린다. 회의 범위를
알면 `[start초] [end초]`로 잘라 입력만 제한한다. 두 값은 원본 녹음의
절대 위치이며 `end초`는 구간 길이가 아니다. 원본은 바꾸지 않는다.
