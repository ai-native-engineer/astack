# Video Cut Editor Workflow

마커 기반 강의·화면 녹화 편집의 전체 생명주기와 종료 조건을 정의한다. 핵심 편집 원칙은 `SKILL.md`가 정본이다.

## 1. 범위와 입력

- 사용자가 지정한 파일만 원본 목록에 넣는다. 넓은 glob으로 preview나 파생 영상을 원본으로 추정하지 않는다.
- 기존 출력은 출처와 계획이 일치한다고 확인되기 전까지 보존하고, 이름이 충돌하면 새 candidate를 만든다.
- 배치 작업도 각 원본의 계획과 QA를 먼저 끝낸 뒤 최종 병합한다.

## 2. 분석과 계획

`scripts/video_cut_workflow.py analyze`로 마커·발화 근거와 draft plan을 만든다. 전체 옵션은 `--help`를 따른다.

### 요청 유형

| 유형 | 계획 방식 |
|---|---|
| 마커 편집 | 각 마커의 실패 구간과 정상 retake를 판단한다. |
| 무음 편집 | `references/silence-cut.md`에 따라 검토한 장기 무음만 계획한다. |
| 혼합 편집 | 마커 구간을 먼저 확정하고 남는 장기 무음을 같은 원본 좌표에 합친다. |

마커가 검출되지 않았으면 발화 삭제 계획을 만들지 않는다. 전사는 의미 확인에 쓸 수 있지만 표시되지 않은 반복이나 말실수를 새 삭제 대상으로 만들지 않는다.

### 마커 판단

| 판단 | 사용 조건 |
|---|---|
| `full_retake` | 마커 뒤에서 실패한 절이나 문장 전체를 다시 말한다. |
| `local_correction` | 실패한 단어나 짧은 구만 다시 말한다. |
| `cut_after_marker` | 마커 뒤의 안내·군말 이후 정상 retake가 시작된다. |
| `skip` | 정상 retake가 없거나 마커가 편집 지시가 아니다. |
| `needs_manual` | 어느 쪽을 보존할지 근거가 모호하다. |

- 비무음 interval은 검출 마커 또는 사용자가 지정한 `source_timestamp`와 연결한다.
- `local_correction`은 실패한 구만 제거하고 직전 발화 segment 전체로 넓히지 않는다.
- `full_retake`은 뒤에서 완전한 절이나 문장이 반복될 때만 실패 take 전체로 넓힌다.
- 뒤에 정상 retake가 없는 tail marker는 EOF까지 자르지 않고 `skip` 또는 명시적으로 검토한 trim으로 처리한다.
- 모든 interval은 원본 타임라인 초 단위로 기록한다.

프로그램이 계획을 합치거나 보정하면 상태를 `draft`로 되돌린다. `scripts/audit_cut_plan.py`와 dry-run을 통과하고, 예정된 모든 발화 접합부의 전사와 오디오를 확인한 뒤에만 `reviewed`로 바꾼다. 경계가 모호하면 렌더하지 않고 `needs_manual`로 남긴다.

## 3. 렌더와 기술 QA

검토된 계획을 `scripts/video_cut_workflow.py render`로 원본에서 한 번 렌더한다.

- 호출 래퍼가 끝났다는 신호만 믿지 말고 encoder 종료와 출력 close를 확인한 뒤 QA를 시작한다.
- 전체 디코드, 예상 길이, 모든 오디오 트랙, 잔존 마커, 장기 무음을 확인한다.
- `join-map`을 렌더된 실제 접합점의 원장으로 삼고 `scripts/audit_waveform_joins.py`와 화면 QA 도구로 모든 오디오·화면 접합점을 검사한다.
- 점수와 전사는 후보 선별 근거다. 잘린 음절, 말의 리듬, 화면 의미를 자동 승인하지 않는다.
- 보정하거나 다시 렌더하면 이전 QA를 무효화하고 수락할 새 파일에서 다시 검사한다.

자세한 화면 검사는 `references/visual-join-qa.md`를 따른다. 오류가 나면 해당 렌더 로그와 candidate 경로를 보존한다.

## 4. 병합과 최종 QA

개별 기술 QA를 통과한 편집본만 `scripts/merge_reviewed_outputs.py`로 병합한다. 전체 옵션과 출력 계약은 `--help`를 따른다.

- 각 파일 연결부에서 앞 문장의 끝과 다음 문장의 시작이 온전한지 먼저 확인한다.
- stream 모양이 같아도 실제 전체 디코드로 결합 호환성을 확인한다.
- 병합 오류가 있으면 입력과 실패 candidate를 보존하고 최종 결합본을 재인코딩한다.
- 수락할 합본의 새 join map으로 디코드, 모든 트랙, 화면·파형 접합점, 마커, 장기 무음을 다시 검사한다.
- QA 보고서는 관측한 값만 기록하고, 제공되지 않은 검사는 완료로 추정하지 않는다.

## 5. 사람 청취 승인

기술 QA 뒤 `scripts/build-listening-review.py`로 수락할 미디어와 join map에 대한 검수 화면을 만든다. 입력·검증 옵션은 `--help`를 따른다.

- 검수자는 접합점뿐 아니라 이전 문맥부터 이어 듣고 종결 어미, 첫 음절, 중복, 리듬을 확인한다.
- 문제가 있는 지점은 원본 좌표와 메모를 남겨 계획 단계로 돌려보낸다.
- 수정본을 만들면 이전 승인과 QA를 재사용하지 않는다.
- 승인 기록은 수락할 미디어와 join map의 해시가 일치해야 한다.
- 브라우저가 열렸거나 자동 검사가 끝난 상태를 사람 승인으로 보고하지 않는다.

## 6. 전달과 정리

- 원본, 검토 계획, 수락할 출력, QA·승인 근거를 서로 구분해 보존한다.
- 생성 로그와 증거는 출력별 artifact 폴더에 모으고 원본 폴더와 섞지 않는다.
- 최종 출력과 승인 기록을 확인한 뒤 `scripts/cleanup_artifacts.py`의 dry-run 후보를 검토한다.
- cleanup은 생성 부산물만 대상으로 하고 원본과 전달본은 보존한다.
- 추가 병합이나 재편집 가능성이 남아 있으면 계획과 join map을 정리하지 않는다.
