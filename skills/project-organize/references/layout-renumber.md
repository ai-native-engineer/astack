# Layout: 번호 루트 폴더

`layout` 모드에서만 읽는다. hygiene 규칙, 승인 게이트, git staging 규칙은 `SKILL.md`에 있다.

## 목표

루트 목록이 프로젝트의 작업 순서를 말하게 한다. 작업 폴더는 `nn-slug`로 번호를 붙이고, 하네스 파일은 번호 없이 둔다.

## 번호 붙이기

- 프로젝트 자체 루프가 있으면 그 순서로 매긴다(관찰 -> 결정 -> 발행 -> 측정). 알파벳순이 기본값이 아니다.
- 번호 뒤 slug는 원래 이름을 유지해 경로가 알아보이게 한다(`research/` -> `02-research/`, `02-근거/` 아님).
- `01-context/`가 이미 있으면 번호를 다시 매기지 않는다. `project-collect`가 `01-context/company/`에 쓴다. 이름을 바꾸면 재수집이 깨진다.
- 번호 없이 두는 것: `AGENTS.md`, `CLAUDE.md`, `.claude/`, `scripts/`, `prompts/` 등 에이전트 하네스.
- 프로젝트가 서로 다른 층으로 취급하는 폴더는 합치지 않는다(예: 글별 아카이브 vs 글을 가로지르는 발견, 정체성 vs 운영 규칙, 합성 데모 vs 라이브 API 놀이터).

`AGENTS.md`가 지목한 예약된 빈 채널 폴더는 남긴다. 재편 중에 잡동사니로 지우지 않는다.

## 옮기기 전에

1. 옛 경로 -> 새 경로 -> 층을 표로 만든다. "합치지 않음" 행도 포함한다.
2. 경로 의존자를 나열한다: `AGENTS.md` 라우팅, 로컬 스킬, `.gitignore`, 스크립트, 상대 링크.
3. 제안 단계에서 커밋을 나눈다:
   - 한 커밋: 이동 + 경로 재작성
   - 나중에: 부피 큰 소스 아카이브, 발표 덤프, 반박된 상태 주장
4. 실행 직전에 디스크를(숨김 파일 포함) 다시 스캔한다. 제안 시점에 비어 보이던 폴더에 그새 샌드박스가 생겼을 수 있다.

## 이동

- 추적 중인 트리: `git mv`.
- gitignore된 무거운 자식(중첩 repo, clone 모음, 프로필 덤프)은 부모와 함께 디스크에서 이동한다. 같은 커밋에서 `.gitignore`를 갱신한다.
- 미추적 트리: 파일시스템 `mv` 후, 이 커밋이 추적을 시작하기로 한 파일만 add한다.

## 경로 재작성

인덱스, 스킬, gitignore, 스크립트의 프로젝트 루트 경로를 재작성한다. 없던 접두사를 만들어 붙이지 않는다.

- 실파일을 편집한다. 심볼릭 링크를 통해 쓰지 않는다(`CLAUDE.md` -> `AGENTS.md`면 같은 치환이 두 번 적용된다).
- 이미 새 접두사인 문자열은 건너뛴다.
- git 히스토리 경로(`git show <sha>:system/...`)와 GitHub API 경로(`gh api repos/...`)는 그대로 둔다.
- 재작성 후 겹친 접두사(`08-08-`, `02-02-`)를 검색해 커밋 전에 접는다.
- 번호 붙은 형제 간 상대 링크는 새 이름이 필요하다(`../playbook/` -> `../05-playbook/`).

## 승인 후

`SKILL.md`의 "제안 후 실행"을 따른다. 이동과 같은 커밋에 `.gitignore`와 경로 재작성을 포함한다. 무관한 미추적 덤프를 그 커밋에 넣지 않는다.

## 출력

```markdown
## Mapping
- <옛 경로> -> <새 경로> - <층>

## Do not merge
- <a + b> - <층이 다른 이유>

## Path dependents
- <파일> - <편집 없이 이름만 바꾸면 깨지는 것>

## Commit slices
- now: <이동 + 경로 재작성>
- later: <아카이브, 덤프, 상태 주장 정정>

## Proposed Actions
- <정확한 이동, 삭제, 인덱스 편집>

## Actions Taken
- <승인 후 실행한 것>

## Needs Decision
- <미결 질문>
```
